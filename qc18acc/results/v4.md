# QC18-ACC v4: 16 pixel rows (128 PEs), registered macro boundaries, distributed crossbar, vs v3

v3 = netlist `qa3_w3.3`, [v3.md](v3.md).  v4 = `compile4/`, `hw4/`, `impl/v4/`, netlist `qa4_w3.3`; spec, addendum and
implementation notes: ARCH.md section "v4".  Same flow as v3: DC W-2024.09 in wire-load mode (WireAreaLowkCon,
enclosed), tcbn65gplus 200a CCS, 3.3 ns at ss; PrimeTime pre-CTS with ideal clocks (ss / tt / ff); PTPX tt 1.0 V 25 C
at 2.5 ns (400 MHz) on the SAIF of the tt-SDF gate-level simulation of test image 0, macro access energy from the ARM
datatables (`macro_dat.py`, "+dat").  Workload: s8kd_s0, one full inference.  No P&R in this step.

Labels: **[M]** measured in simulation (RTL / gate-level cycle counters, bit-exact checks); **[S]** synthesis
estimate (DC / PrimeTime area and timing, PrimeTime PX power, all on the pre-route netlist with the WLM and ideal
clocks); **[Mod]** model (cycle model, datatable macro access energy, op counts from the weight image, derived bounds).

## 4. Implementation choices (ARCH v4 [impl])

* **Activation macro sweep** (`impl/v4/sweep_result.txt`, ss, macro area incl. ring) [S]: per bank 128 b x 256 words.
  rf_sp_adv 256 x 64 mux 2: 32 180 um2 (2 per bank = 64 360); mux 4: 40 148; sram_sp_adv 256 x 64 mux 8: 80 172;
  **rf_sp_adv 256 x 128 mux 2: 55 525 um2** (also with a write mask, wp_size 8 or 32: same area); sram 256 x 128 mux 8:
  146 837; illegal: rf mux > 2 at 128 b, sram mux 4, sram 256 words at mux 16.  Chosen: 48 x rf 256 x 128 mux 2 with a
  32-b write mask (host 64-b half writes) = **2.665 mm2**, against v3's 48 x 512 x 64 = 2.546 mm2 (**+4.7 %**, the cost
  of 16 banks at the same capacity); 96 x 256 x 64 halves would cost 3.089 mm2 (+21 %).
* **Registered boundaries:** every macro pin (A, D, CEN, WEN) is driven by a flop with no logic in between, every macro
  has its own output register (the v3 hold register and hold mux are gone).  Read latency 3 (request t, pins t+1, Q t+2,
  output register t+3); array data reach the window at t+6 (v3 t+3), issue -> capture 6 cycles.
* **Hold (addendum):** `impl/v4/constraints.sdc` puts `set_min_delay 0.4` on the 736 A / D / CEN / WEN pins of the
  weight and param macros; the written netlist SDC carries them for P&R.  DC did not insert hold buffers at any macro
  pin (in-compile min-delay cost 0; v2 / v3 left their pre-route macro-pin hold violations to P&R too, v3 658
  endpoints).  Pre-CTS hold [S]: weight / param pins -0.56 ns tt with the 0.4-ns rule (-0.16 ns without it), act-macro D
  pins -0.058 ns tt (6 144 paths, write-data flop -> D directly), every register endpoint >= +0.017 ns.  A DC variant
  with an incremental hold-only compile is in section 10.

## 7. Executed-op TOPS (ARCH v4 addendum: metric of record)

ops = 2 x executed MACs; an 8x8 QC block executes 8 MACs per nonzero term (<= 2 terms, <= 16 MACs, never 64); a
ternary x int8 MAC is one MAC (2 ops), like a 1b x 1b MAC.  `python3 -m qc18acc.compile4.ops <export>` counts the
nonzero terms of the weight image as the array consumes it [Mod]: **128 541 440 conv MACs + 5 120 FC MACs =
128 546 560 MACs = 257.1 Mops per image** (dense-equivalent 555.4 M MACs, x4.32).
Peak = 128 PEs x Kb 2 x 16 = **4 096 MACs = 8 192 ops per cycle**.

The v3 window register takes its data from 24 macro Q pins (8 banks x 3 buffers, through the hold muxes: 80 start
points per bit), which is the hub that did not route (`pnr_v3.md` section 11).  In v4 no xbar stage sees a macro Q pin:

control), the array path has at most 9 (window: 4 stage-A registers + hold + shift + control), stage A 6, bank select 5,
write data 5.  The price is cells: 49 064 xbar leaf cells (166 388 um2) vs 23 197 (59 994 um2) in v3, x2.1 for twice the
rows, because every stage is a register stage of the full 16 x 128-b width.  Whether the stages spread along the macro
rows as intended is a P&R question (not run here).

### 9.3 Prediction (55-60 uJ) vs measured 62.68 uJ, mechanistically

* **PE energy per QC block unchanged (predicted): x0.994 [S]** (4.157 -> 4.131 pJ; per group within +-7 %: the PE
  is v3's, each block costs the same, 2x the PEs run half as long).
* **Weight reads per image halve (predicted): weight-macro energy x0.506 [S] + [Mod]** (138 120 -> 69 376 reads per
  image: one 160-b word now feeds 16 rows instead of 8).
* **Leakage per image halves (predicted): x0.675.**  Leakage power rises 21.2 -> 27.5 mW (+786 kGE of logic, larger
  act macros), so time x0.520 gives x0.675, not x0.5.
* **Control per image halves (predicted): x1.055 for AGU + xbar + seq + host + glue, and act-buffer logic x3.16
  (0.54 -> 1.72 uJ).**  Seq / AGU / host are per cycle and do halve, but the xbar moves the same data volume per image
  through more register stages (stage A, 16-slot window), and the registered boundary adds per-access energy: every
  128-b read passes the macro output register and the bank-select register, every write the group and bank write-data
  registers.  This is the energy price of the routing fix: +1.3 uJ / image (2 %).
* **Not in the prediction:** activation macros x0.651 (7.25 vs 11.14 uJ: a 256 x 128 read costs 23.5 pJ vs 2 x 17.5
  for two 512 x 64 halves, and leaks for half the time), PPU x1.025 (same output words, 8 instead of 6 stages, two
  units).
* **Why 62.7 and not 55-60:** 54.3 of the 62.7 uJ are work-proportional and do not scale with the cycle count (PE
  36.0, PPU 11.0, act macros 7.2); the cycle-proportional parts of v3 (leakage 4.3, weight macros 6.1, control 2.3,
  param 0.6 uJ) were only 13 uJ, so halving them could save at most ~6.5 uJ (68.5 -> ~62), and the boundary / xbar
  stages gave 1.3 uJ of it back.  Executed-op efficiency: 4.10 TOPS / W (v3 3.76), 0.488 pJ per executed MAC [S].

## 10. Deviations, open issues

* Act macro: one 256 x 128 rf per bank with a write mask instead of two 64-b halves (smaller; the head reads a whole
  word and selects the half).
* Pre-route hold at the macro pins is not fixed by DC (as in v2 / v3); the 0.4-ns min-delay rule on the weight / param
  macro inputs is in the netlist SDC for the post-route hold ECO.  Side run `qa4_w3.3h` (`impl/results/qa4_w3.3h`, DC
  plus `compile -incremental -only_hold_time`) [S]: +8 154 um2 (+0.1 %, 4 775 hold cells), setup unchanged, 72
  endpoints left (weight / param address pins, up to -0.50 ns tt against the 0.4-ns rule): fixing the pre-route hold
  of the registered boundary is cheap, the residue is the shared weight-address register driving 3 macros.  Not the
  netlist of record (kept on the v3 flow for comparability).
* The tt-SDF GLS reports 74 186 hold-check messages on weight / param macro address pins (same cause); with
  `+no_notifier` the run is bit-exact.  v3's SDF run had none because its macro pins were driven through mux logic.
* PPU: 32 lanes as two v3-style 16-lane units with separate write / residual ports, 8 register stages per lane (the
  residual word returns 5 cycles after its request).
* Not done (out of scope): P&R of v4 (whether the distributed xbar routes, routed fmax and area, the routed executed
  TOPS / mm2 of the target), the ablation at 16 rows, the 0.8 V point.
* All power numbers are pre-CTS, WLM estimates; macro access energy is the datatable model (the macro .lib CLK energies
  are 0).
