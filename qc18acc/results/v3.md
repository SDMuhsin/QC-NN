# QC18-ACC v3: two QC blocks per PE per cycle (Kb = 2), vs v2

v2 = netlist `qa2_w3.3`, [power_v2.md](power_v2.md) (unchanged, still the default build).  v3 = `compile3/`, `hw3/`,
`impl/v3/`, netlist `qa3_w3.3`; spec and deviations: ARCH.md section "v3 (implemented)".  Same flow as v2: DC
W-2024.09 wire-load mode with WireAreaLowkCon (enclosed), tcbn65gplus 200a CCS, 3.3 ns at ss; PrimeTime pre-CTS,
ideal clocks; PTPX tt 1.0 V 25 C at 2.5 ns (400 MHz) on the SAIF of the tt-SDF GLS of test image 0; macro access
energy from the ARM datatables (`macro_dat.py`, "+dat").  Workload: s8kd_s0, one full inference.

Labels: **[M]** measured in simulation (RTL / gate-level counters, bit-exact checks); **[P]** PrimeTime PX power of
the synthesised netlist with the gate-level SAIF (pre-CTS, WLM; macro access energy **[Mo]** from the datatable
model); **[S]** synthesis estimate (DC / PT area and timing, WLM, pre-CTS); **[Mo]** model.

### 5.3 Predictions vs measurement, mechanistically

* **Image energy ~70 uJ -> 68.5 uJ (-2.2 %).**  92.4 - 68.5 = 23.9 uJ saved, by block: PE array -16.8 uJ
  (53.0 -> 36.3), PPU -2.8, weight macros -1.3, act macros -1.3, AGU / xbar / seq / host -0.7, param macros -0.4,
  drain / head / wrappers -0.6; across all blocks 4.5 uJ of it is leakage (same leakage power, time x0.509).
* **Cycles x0.53 -> x0.509.**  The array work halves exactly (busy 136 320 -> 68 736 = S per tile halved, stem
  9 = 9 with its zero odd block); the fixed parts (head 868, param load 4 800) are smaller than assumed in the
  prediction, and the drain-bound stem / shortcut passes halve too (drain 64 -> 32 / 128 -> 64).
* **PE energy per block x0.7 -> x0.684** (pe_power.tcl, per-PE groups in fJ per QC block): clock gates + register
  clock pins x0.536 (2 077 -> 1 114 fJ: the same 320 flops per PE are clocked once per two blocks: per-PE clock power
  708 -> 746 uW, +5 %, at half the cycles); accumulator data x0.585; adders x0.759 (v2 2-term add 1 249 + accumulate
  add 1 625 = 2 874 fJ; v3 fused trits + 4 terms + accumulate 2 181 fJ: one 20-b carry-propagate add per two blocks,
  the 4-term compression is the added work); rotators x0.87 (same work per block); shadow / capture muxes x0.83 /
  x0.88 (same tiles, half the clocked cycles).
* **Glitching of the fused sum.**  SDF / zd per PE: v3 `u_acc` 1 460 / 829 uW = 1.76; v2 `u_tadd` + `u_acc` 980 /
  523 = 1.87 (accumulate add alone 2.98).  Fusing the term adds and the accumulate into one adder tree (no ripple
  sum feeding a second ripple add) keeps the glitch factor below v2's despite 4 terms.  Whole PE SDF / zd: v3 1.37
  (2 749 / 2 006 uW), v2 1.37.
* **Leakage + control x0.55: leakage x0.491 (holds), control x0.765 (misses by +39 %).**  Leakage power is
  unchanged (21.2 vs 22.0 mW; the smaller act macros leak less, the larger logic more) and scales with time.  The
  control rows (sdf, mW -> uJ / image): AGU 1.41 -> 1.43 mW, seq 1.36 -> 1.37 mW, host 0.49 -> 0.49 mW, i.e.
  per-cycle constant, energy x0.51 as predicted; but the xbar (kw window + lane mask + code register) goes 3.70 ->
  7.14 mW (x1.93): it holds and shifts 8 x 128-b words and 160 code bits per cycle instead of 8 x 64 / 80, so its
  energy per image is set by the data volume (1.48 -> 1.45 uJ), not by the cycle count.  The prediction treated the
  whole AGU + xbar + seq block as cycle-proportional control.
* **Not predicted, observed:** PPU energy x0.790 (13.5 -> 10.7 uJ) for the same output words: idle-stage clocking
  halves with time and the multipliers are 20 x 31 instead of 32 x 31; activation macros x0.896 (same 64-b data
  volume: 453 k macro reads / image in both; the rf_sp_adv 512x64 costs 17.5 pJ / read vs 16.1 pJ for the sram

## 6. Deviations from the spec, open issues

* Act macro: rf_sp_adv 512 x 64 mux 4 (densest legal; 512 x 128 only as sram mux 8, larger) -- as the spec allowed.
* The stem reads both halves of its input words (the high half is zero, written by the host) instead of gating the
  odd half; the odd weight half holds zero words for the stem.  Cost: 1 152 extra 64-b reads / image (negligible).
* `qa_seq.sv`, `qa_sram.sv`, `qa_bankmem.sv` are shared with v2 unchanged (v3 package: 9-b act addresses, so the
  descriptor base fields are truncated to 9 b; all bases are 0).
* PPU keeps v2's 64-b rounding sum after the 20 x 31 product (bit-exact for any sh <= 63); a narrower sum would need
  a compiler bound on sh.
* Not done (out of the task scope): the QC vs ternary ablation at Kb = 2 (ARCH v3 "Why"), P&R of v3, the 0.8 V point.
* Power numbers are pre-CTS, wire-load-model estimates (no clock tree, no extracted wiring), like v2's; the macro
  access energy is the datatable model (the macro .lib CLK energies are 0).
