Every probed edge of the SDF run is the zd 3.5 ns edge plus 140..220 ps of clock-to-Q, from streamer start
20645243.5 ns to streamer end 20645495.5 ns. The streamer is 5 cycles shorter than in RTL because of the
clock: RTL and gls_zd.log run the cluster at chimera's default 2 ns. Rerunning zd at 3.5 ns
(KUL_GLS_SIMARGS=-G/tb_chimera_soc/fix/vip/ClkPeriodClu=3500) gives 72/71 as well. That zd run is not in
results/gls_zd.log. Only the streamer differs: GeMM and SIMD are the same at both clocks.

Root cause of the earlier hang: the same one as the Snitch SDF run. chimera's RTL changes the cluster inputs
0 ps after the clock edge, and some port-to-flop paths are about 10 ps. The tt SDF gives those flops
hold windows that reach past the edge (negative setup / positive hold on D). Questa models negative
$setuphold limits with internal delayed D/CP, so such a flop samples the input of the NEXT cycle and
the check passes on the delayed signals. Nothing is reported, but an AXI handshake is seen one cycle
early. The STA assumed 0.7 ns input delay, so these paths meet hold there. The fix is all three items
above together. The input delay was not bisected on KUL. The reset item was not the cause of the hang:
the old run reported 0 reset (CDN) timing errors.
Pitfall found and fixed: vsim -G of the TB's time parameter ClkPeriodClu takes simulator units (ps). "3.5ns"
gave a 4 ps clock.
