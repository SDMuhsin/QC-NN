# R44: why the clock-gated subtrees are late (hub g_wbc and others)
Labels: [M] measured, [S] from a report or source, [E] estimate. tau6 only. Repo unchanged except this file. Nothing committed.
Scripts and logs: tau6 `/tmp/ckp908/qc18bacc/r44/` (lat44/leaf44/fwd/icgsplit44.tcl, arm44.sh, r44_results.txt). Arm odbs deleted.

## The bug
The flow splits physically separated ICG fanout **after** CTS. It should do it **before** CTS.
* DC merges registers that share an enable into one ICG (max fanout 32), whatever their placement. Hub `clk_gate_g_wbc_ha_reg_7__7_`:
  27 ha flops at x 3610-3885 + htp/hct_reg_0/1 at x ~800; `..._hdo_reg_7__6_`: 28 flops at x ~3800 + hoy/hh at x ~800 (gap 2970 um) [M].
* TritonCTS (OR 2.0-12381) centres each gated H-tree on the sink bounding box, here x 2337, 1.1 mm west of the ICG.
  Its 4 equal-capacity leaves then assign near sinks to the west branches. 4 ha flops at x 3825-3875 hang under
  `clkbuf_2_1_0` (x 1899), then wire9, wire8, wire7: a 2 x 2 mm detour [M] (r35_hubC cts.odb, r40_hub finish.odb).
* The flow's fix is `impl/r37/icgclone37.tcl` (QB37_ICGCLONE). It runs on the routed db, after CTS. It moves only the far
  sinks to a clone. It never rebuilds the original gated tree. In r40_hub the stale tree is still there: wire10 and wire13 drive
  0 loads (dead branches). wire7 still clocks ha_reg_7__7__100..103 through the detour. wire15 does the same for 3 hdo-ICG flops [M].
* The 3 r40_hub tt hold violators (ha_reg_7__7__102/101/100, -0.02) are exactly the wire7 sinks: PT capture CP 2.41
  (ICG CP 1.38, Q 1.46), launch 1.48 [S] (rpt/pt_hub_tt_min.rpt).
* -balance_levels does not compensate. It equalises buffer count: the ungated sinks get 5 co-located CKBD4 (+0.13 ns).
  The gated path gets the ICG, 4 long H-tree stages and 4 repair_clock_nets wire buffers (+1.03 ns) [S].

* Chip top: not measured (no top db on tau6); r11/top.cfg has no ICG handling by default (QB11_ICG 0). R42 cm_de -> stb

## Impact
* Hub: R33 defect 3, R34 '~1.2 ns late', the R37 clone and the R40 hold residue all trace back to 2-3 bimodal ICGs (0.5-0.8 ns
  late at CTS, 0.93 in routed PT); post-route repair can only pad data paths. Act / column: +0.08-0.17 ns systematic skew [M].

## Suggested fix (opt-in, defaults unchanged)
1. **QB44_SPLIT=<gap_um>** (400 tested), `icgsplit44.tcl` as PRE_CTS_TCL: a CKLNQD* whose sinks have an x or y gap above it is
   cloned (same E / TE / CP nets), the smaller group moves to the clone, then r34/cts_pre.tcl runs (r6c also sizes / moves the
   clones). Hub: QB22_SET_X "PRE_CTS_TCL .../icgsplit44.tcl"; retire QB37_ICGCLONE (a post-route clone cannot fix a built tree).
2. Act, column and top: the same hook, plus r6c icg.tcl (size and move to centroid) in their PRE_CTS. Untested. Expected to
   remove most of the CKLNQD1 delay (0.11 -> ~0.06 ns p50) [E].
3. No CTS rerun on r40_hub: ECO the wire7 / wire15 sinks onto the wire5-6 / wire11-12 nets and delete the dead west branches
   (at CTS 2.114 -> ~1.835 ns on those flops [E]); the tree stays ~+0.45 ns late, so (1) is the real fix.
