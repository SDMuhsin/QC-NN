# R69: qb_col_blk sign-off — why the DMSA ECO left ml max_tran 3 / ml_rcb noise 2, fix, last round

## Predicted failure points (written before launch)

Chain on r68 (label eco): `col eco r68` -> `col calibre r68` -> `col post r68` -> `col views r68` (queue r69q1).

1. eco (PT DMSA): the scenario-side `qb_eco_buffers` call via `remote_execute` returns no list -> error at line
   "no ECO buffer list" (new code path).
2. eco (ICC2): the noise buffer of the `none` pass has no PT location; `place_eco_cells` may put it mid-net, so the
   ml_rcb noise on s_rd[523] can persist (or move), and post fails on noise again.
3. eco: the BUFFD16 inserted on HFSNET_577 (ml max_tran) may need site space that legalisation moves cells for
   -> new hold / tran at ff / ml.
4. post: a new 1-3 ps ml max_tran on another wire-dominated net after the fill-aware re-extraction (fill adds cap
   that PT did not see when it fixed).
5. calibre: unchanged risk (LVS / DRC / antenna were clean in r68); a new buffer near the south edge could add an
   antenna or a density marker.

## Diagnosis [M] (r68 label eco; single-scenario PT probes with the DMSA scenario setup of drv_eco.tcl)

PT's unfixable reasons (r68 pt_eco.log, round 2):
- ml max_tran, 3 pins `u_core/g_col_0__g_grp_{0,1,2}__u_br/c_q_reg_220_/D`: reason **D** (high density).
- ml_rcb noise, `.../g_fq_3__g_fc_0__g_fi_6__u_lf/u_res/U76/A1` and `U74/B1`: reasons **I P** (buffer list
  cannot fix; driver is a port).

### ml max_tran
- Net u_core/HFSNET_577: one ICC2 HFS BUFFD16, 8 DFQD1 D loads, routed 1571 um (y 1438 -> 2931).
- The driver output slews 0.030 ns. The far loads slew 0.327 ns against the ml library pin limit 0.3234. The net is
  wire-dominated, so upsizing the driver cannot help (and the next size up, BUFFD20, is kit dont_use).
- Reason D is not real. ICC2 local utilisation at the 3 loads: std cells 0.47-0.64 plus fill/decap 0.23-0.29 in
  20-50 um boxes. Core utilisation is 0.61.
- Not the cause: dont_touch (the net and driver are not dont_touch) or ml being left out of the fixers (ml is
  in every DMSA fix; it counted 3 in "Violation Totals").
- Cause: our own hand-picked `-buffer_list {BUFFD2 BUFFD4 BUFFD8}`. The probe runs fix_eco_drc in occupied_site mode:
  - with that list: 3 left, reason D;
  - with every BUFFD* the dont_use list allows (D0 D1 D2 D3 D4 D6 D8 D12 D16): fixed by 1 BUFFD16, max_tran 0.

### ml_rcb noise
- Victim net s_rd[523] is an input port. Its driving cell is the site.tcl QC_DRV_IN BUFFD4. The port is at the south
  edge (333.7, 0). Routed 797 um. Coupling 0.13 pF.
- The noise bump is 0.47 V high and 0.49 ns wide; the CCS immunity is 0.42 V, so slack is -0.05 V. The main aggressor
  is ropt_net_2666 (0.16 V).
- Probe results:
  - occupied_site mode, every allowed buffer: still I P, no change.
  - physical_mode none, BUFFD2/4/8: fixed by 1 BUFFD8, noise 0.
- Cause: PT's physically aware mode cannot place the buffer a port-driven victim needs.

## Fix (signoff/pt/drv_eco.tcl, shared by every block) [S]
- `qb_eco_buffers` builds the buffer list from the library: every BUFFD* that is not dont_use. The DMSA master
  gets it from a scenario process. The list is used by fix_eco_drc and by the setup fix_eco_timing. The hold fix keeps
  BUFFD1 / BUFFD2.
- `qb_eco_drc` runs each DRC type in two passes:
  - first physically aware (occupied_site);
  - then `-physical_mode none` for whatever is left.
  - Cells from the second pass have no PT location; flow/icc2/eco.tcl `place_eco_cells` places and legalises them.
    That path already existed.
- No limit, margin, waiver or dont_use change.
