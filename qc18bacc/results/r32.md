# R32: hub timing slowness, root cause (unbiased bug hunt)
Labels: [M] measured, [S] single run, [E] estimate. Run analysed: R31 arm A (r31_A, 2.30 ns, tau4); arm B (r31_B, tau6)
checked for the same mechanism. Scripts: scratch on tau4 / tau6 `/tmp/ckp908/qc18bacc/r32/` (listed in sec. 7).
Nothing in the repo changed except this file. No default changed, nothing committed. Tau times are UTC-6.

## 1. The bug
**`QB_IO_LAT` = 1.30 ns is stale.** It is the clock-insertion delay L by which the post-CTS IO budget is shifted
(`impl/pnr/slice_post_cts.tcl`: inputs +L, outputs -L; set in `impl/r28/run28.sh`, `impl/r21/run.sh`, `impl/r22/run.sh`).
It was measured once, in R21, on a different netlist / floorplan (r21 cts.odb p50 1.30). On the R31 hub, OpenROAD's
own clock-pin latency at the same point (db/cts.odb, placement parasitics, `impl/r21/clk_lat.tcl`) is p50 **1.39**
(gated 1.392, ungated 1.386; p10 1.30-1.35, p90 1.44) [M]. With L 0.09 ns too small, every input min delay
(0.05 P + L) is 0.09 ns early relative to the hub's real clock, so the post-CTS hold repair "fixes" in2reg hold
violations that do not exist.

The damage is not the hold buffers' own delay. It is where they go and what legalisation does next:
1. Phantom in2reg hold on the north-edge input buses (`wb_fy -> g_wbq_fyq / g_pcol fyi`, column `b2 -> b2r`):
   the hold repair puts its buffers on these 550-um wires, and because they drive the long wire it upsizes them
   (BUFFD16). They land in rows mid-wire, which is over the pcol adders (y ~ 1440).
2. In the 160 x 100 um window over `u_head/g_pcol_4__u_pc`: **406 BUFFD16 + 51 BUFFD1 hold buffers, 4 322 um2**
   added to 10.8k um2 of cells in 16k um2 [M]. The sinks of those buffers are 329 fyq regs, 60 b2r regs and pcol fyi
   regs, all in2reg.
3. `detailed_placement -max_displacement 500` then has to clear the overlap, and it **evicts the pcol cells**:
   268 cells leave the window (224 of pcol4). The 12-stage FA ripple `intadd_104` goes from a **6.6 um** mean step
   between consecutive FAs to **61.4 um**, and the pcol4 bbox grows from 235 x 198 to 282 x 209 um.
4. FA-to-FA nets go from 1-2 fF to 15-30 fF (FA1D0 delay 0.06 -> 0.15-0.24 ns per stage), and the fyi Q net goes
   from 0.034 to 0.103 pF. **The pcol path `fyi_reg_207_ -> s4_reg_4__14_` goes from +0.665 ns slack (cts.odb) to
   -1.509 ns** (OR, same parasitic model), and to -1.90 ns in PT (238.1 MHz).
5. `QB_RT_LOOPS 0` (inherited from R24 / R26: `impl/r28/run28.sh`) means **no setup repair runs after the hold
   legalisation**. The last setup repair saw the pcol path with positive slack, so it never touched it, in either
   arm. That is why R31 saw "A ~ B, FA1D0 never upsized". The damage goes straight to sign-off.

R31's reading "fyi -> s4 is an RTL / synthesis limiter (2.1 ns tt)" is wrong. In DC's own view (DC netlist + DC
topo SPEF, PT tt) the same path arrives at **1.229 ns** with 1-2 fF FA nets [M]. In OR at cts.odb it is 1.35 ns.

**Fix check (only L changed, 1.30 -> 1.39):** in OR on arm A, the hold repair still closes hold (12 endpoints) and
nothing is evicted, so the pcol path stays at +0.67 and reg2reg goes -1.51 -> -0.43 ns (sec. 3). Routed and signed off
in PT on arm B (2.80 ns, DR 0): the pcol paths go from -1.180 to +0.514 (tt) and from -4.047 to -0.954 (ss). reg2reg
is 251.3 -> 261.3 MHz at tt and 146.0 -> 177.8 MHz at ss; all-path is 209.2 -> 223.0 at tt and 143.3 -> 151.2 at ss.
The next tt limiter, the b2w_q pointer broadcast (-1.03), is structural (sec. 4). Arm A's PT was lost to a tau4 outage.

## 5. Other own-side defects found (secondary, not the reg2reg limiter)
1. **PT vs OR clock latency gap, so L is wrong in PT as well.** PT routed latency p50 1.70 (R31 clk31). OR at cts is
   1.39. At the pcol flop: OR 1.401 (cts) / 1.439 (cts_rt), PT 1.69. Part of this is the clock trunk: `clk -> wire4 ..
   wire1 -> clkbuf_0` is 0.66 ns in PT vs 0.51 in OR (net caps 0.14-0.26 pF). Some trunk nets route 2-3.7x their
   estimate (clknet_5_7_0_clk 97 -> 364 fF, net6 / 11 / 12 / 19 160 -> 260 fF). The clock-net cap overall agrees
   (SPEF / estimate 1.03, p50 1.01, 14 698 nets) [M]. Sign-off with L 1.30 against a 1.70 tree costs reg2out 0.4 ns
   and creates the PT in2reg hold flood (R31). L has to be measured per run and per view (OR at cts for the repair,
   PT routed for sign-off), not carried as a constant.
2. **The OR-side SPEF is unreadable.** OpenROAD's `read_spef out/qb_hub_tt.spef` (the non-PT copy, `run_pnr.sh`, used by
   `or/sta_post.tcl` and any OR post-route check) stops at line 34 214 (STA-1650 net
   `clknet_0_u_head/g_pcol_0__u_pc/net558218` not found, then STA-1657 syntax error: that net has an empty `*CONN`).
   The R31 fix QC_SPEF_UNESC only applies to the `--escape-divider` (PT) copy. In OR with this SPEF, the pcol path shows
   0.50 ns clock latency and a 1.09 ns data path, so any OR post-route timing is meaningless [M]. PT is not affected
   (SPEF total cap 11 139 pF = routed wirelength x layer C, exact).
3. **The post-CTS setup repair edits the clock tree.** 21 trunk `clkbuf_*` CKBD16 -> BUFFD16, and 13 macro ICGs
   `g_mac_u_cga` CKLNQD2 -> CKLNQD16/4 (the S / map macros' CLKA). The effect is small (trunk = common path; 13 macro
   clocks), but clock cells should be dont_touch after CTS [M].
4. DC's chip WNS (-4.46 ns, r26_ptr) is an artefact path through the column-ETM `act_o` feed-throughs (8 x
   0.35 ns + ETM setup 2.20 + latency -0.9). It does not starve the hub logic: in DC's view the pcol path is 1.23 ns
   and 8 913 of 9 214 PT-DC violators are within -0.5 ns [M]. Not a cause.
Ruled out [M]: dont_touch left on nets / insts (0 / 0 in cts_rt); the `*D0` dont_use freezing D0 cells (64k D0
instances were resized); captable / SPEF RC scale (layer R / C plausible, total SPEF cap = WL x C); placement before
CTS (chain step 6.6 um at place and cts; fo1 p50 5.8 um).

## 6. What to change (opt-in, not done here)
- Set QB_IO_LAT from the run's own cts.odb (`clk_lat.tcl` p50) before the post-CTS repair. Re-measure it in PT on the
  routed db for sign-off and ETMs (or use PT's own `(max + min) / 2` already computed in `pt_hub.tcl`).
- Keep at least one setup pass after the hold legalisation (QB_RT_LOOPS >= 1). Optionally legalise the hold buffers
  with a small `-max_displacement`.
- Fix `def2spef.py` for the OR copy (apply the unescape to both copies) so OR post-route numbers can be trusted.
- dont_touch the clock tree (clkbuf_*, ICGs) during the post-CTS repair.
