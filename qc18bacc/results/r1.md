## Structure and pipeline

16 rows (output pixels) x 8 columns (8 output channels) of `qbc_pe` (KB 36, ACC_W 20), 8 x 36 decoders, 256 fused lanes
(`qbf_lane`, MW 28, sel 4 b, no pre-clamp), 32 wide lanes (`qbcw_lane`), two per-channel parameter banks. Pure datapath:
every control comes per cycle from the ports (R3's sequencer generates them; the bench's generator plays that role).

| stage | cycle (item n) | what |
|---|---|---|
| code port | n - 1 | 8 cols x 36 8-b codes + item controls {valid, first, plane, neg, stem, g3n, cap, cmp} |
| decode | n - 1 (comb) | 288 `qbc_dec` (8 b -> 10 b) + per-column weighted nneg NNw (10 b) |
| BR | edge -> n | broadcast register: one copy per (8-row group, column): codes 360 b, NNw, controls, T2 |
| act port | n | per row 36 bytes (byte j = tap * 4 + group; 1x1: group j) |
| PE S0 | edge -> n + 1 | input registers (a 288 b, c 360 b, NNw, controls) |
| PE S1 | edge -> n + 2 | per lane i, group g: u_gi = popcount of 18 terms; s_i = sum_g w_g u_gi - NNw (w = 1,1,1,1 or stem 1,2,4,+-8); s_i 10 b |
| PE S2 | edge end n + 2 | acc_i = (first ? 0 : acc_i) +/- (s_i << plane); cap: shadow <= acc; cmp: b2_i <= (acc_i >= T'_i) ^ inv_i |
| T2 port | n + 1 | per column 8 x {inv, T'[15:0]} (sign(g) folded by the compiler) -> BR -> comparators at S2 |
| b2 out | n + 3 | 1024 b + b2_vld |
| PPU ctl port | t | f_vld / f_src / f_sh / p_ld, w_vld / w_sh / w_ld (registered at the boundary) |
| lane early | e = t + 1 | fused lane (q, c, i) <- PE (q, c) shadow[i] (rows 0..3), f_sh: shadow row r <- r + 4 (4 cycles / tile); wide lane (q, c) <- PE (q, c) shadow[7], w_sh: lane-serial chain via PE (q + 4, c) (32 cycles / tile), wide bank rotates |
| lane late | e + 1 | s_rd (sv: r / s_in, 17 b), w_r (19 b), fused late params (P1) |
| outputs | e + 3 (fused) / e + 4 (wide) | s_out / r / u8 (17 b) + b1_next; wide y (19 b) + b |

Stem: group g of stem cycle h carries image plane 4h + g (plane = 4h, g3n = h == 1 negates group 3 = plane 7); the
weight store replicates the 9 group-0 tap codes into groups 1..3. b6.hm runs as fused-lane jobs (f_src = 1: x = s_rd at the
early cycle, 256 values / cycle).

Timing (PT, pre-CTS ideal clock, same flow as micro.md): **tt 500.4 MHz** (meets 500 MHz; as for the micro blocks DC

Critical paths: tt (PT) fused-lane S0 -> multiplier -> P register (`u_lf/u_rin -> u_rp1`); DC's worst: PE S0 code
register -> group popcounts -> weighted sum -> s register (`u_pe/u_in/c_q -> u_pop/s_q`); ss: wide-lane 20 x 31
multiplier (`u_lw/m0 -> p1`, 3.18 ns). The small config `qb_core_s` (8 x 2: 16 PEs, 64 fused, 8 wide lanes, 13 min)
gives the same per-element areas (PE 25 405, lane_fn 6 082, wide 9 213) and tt 500.4 / ss 316.6 MHz (tt path: code port
-> decoder -> NNw -> BR register, i.e. the 20 % input-delay budget). The core is no slower than its micro blocks
(micro.md: ss 314-322 MHz): no core-level path (broadcast, drain, banks) is critical in WLM synthesis. Long-wire
effects of the broadcast / drain at placement are not modelled (R5).

## Deviations from ARCH v1.2 and why

1. **nneg per column, not per PE**: the -1 trit count depends only on the column's codes, so it is computed once at the
   decoders as the weighted NNw = sum_g w_g nn_g (10 b) and broadcast; the PE subtracts it at S1 and registers s_i
   (10 b signed) instead of u_i (7 b) + nneg. Saves 120 of 128 nneg popcounts per column; S2 shortens to shift + add.
2. **Stem group-shift mode** = 4 group popcounts per lane (18 terms each) weighted (1, 2, 4, +-8) in S1, plane = 4h at S2.
   Binary mode reuses the same 4 group counts (weights 1). This split + weighted sum is why the popcount block is 14.1 k
   (KB 32 micro: 10.8 k) and the PE +10 % over the 23.1 k estimate. Stem codes of group 0 are replicated into groups 1-3
   by the weight store (compiler), not by hardware muxes.
3. **T2 port** carries per column 8 x {inv, T'} two cycles after the cmp control (only one register stage for T2; no
   per-PE threshold registers): sign(g) is folded by the compiler, T' = clamp16(1 - T2), inv = 1 for negative channels
   (exact: c1 accumulator domains lie inside 16 b).
4. **Drain topology**: fused = parallel row shift (PE r <- PE r + 4, rows 0-3 feed 4 x 64 lanes, 4 cycles); wide =
   the lane-serial chain extended through PE r + 4 (32 chains, 32 cycles); the shadow needs a 3:1 input mux (1.8 k / PE
   incl. 160 flops). Wide lanes take the column's 8 parameter records from a rotating bank (no 8:1 muxes).
5. **Parameter ports per tile**: fused bank = 64 channel records (sgn, bias 16, m 28, sel 4, h 16, T 16) + pass modes,
   P1 = copy of the late fields one cycle after the load so back-to-back drains / hm jobs never clobber a late operand;
   wide bank 64 x (sgn, bias 20, m 31, sh 6, T 21). The wide lane has no h (block 6 pre-adds the bias, h = 0) and takes
   r as a late operand like the fused lane.
6. **Interface contracts for R2 / R3**: codes and item controls lead the patch by one cycle (decode + broadcast stage);
   PPU controls are explicit per cycle (no drain counter in the core); b6.hm feeds x through s_rd at the early cycle, so
   one bubble is needed when an hm job directly follows a drain (shared s_rd port; once per image); a tile whose int8
   items are all skipped needs one all-zero item (never occurred on the 4 images).
7. **Broadcast stage**: one register copy per (8-row group, column) after the decoders, and the PE keeps its own S0
   code registers (as qb_pe): code path = port -> decode -> BR -> PE S0 -> popcount. The PE S0 code registers
   (360 b x 128 PEs, ~0.32 mm2) are redundant with BR at 8-row fanout and are the largest optional saving
   (needs a placement check of the BR -> popcount wire).
