# R26: QB_TOP_PTR (pt lookup registered one cycle early) - RTL review + hub re-implementation
Labels [M] R26 script, [S] tool, [E] estimate, [R] recommendation. Base: r24_d65t (tau5, netlist r10_rpw, pn2 floorplan, gpl incr/gpl2 density 0.65, QB_TNS 10, QB_RT_LOOPS 0).
## A. Review of the uncommitted QB_TOP_PTR diff (hw/rtl/qb_top.sv)
- fo path: fo = fdl[D + 7] and fdl[D + 7] <= fdl[D + 6] is an unconditional shift with the same async reset, so
  fo.pi(t + 1) = fdl[D + 6].pi(t). fo_pq <= pt[fi] with the same-cycle pt write (h_we && h_sel 3, h_data[88:0])
  forwarded = the pt state after the edge = what pt[fo.pi] reads in the next cycle. Equivalent [review].
- b2 path: pin repeats the FIFO always_ff exactly: pop = (n != 0) && (j == b2_nl) (b2_nl from the registered b2w, as
  in the FIFO), slot = n - pop, capture into slot 0 overrides the pop shift (last assignment wins), overflow
  (slot > 1) leaves the head unchanged. b2f_pi is not touched by the WBQ deferred write (only b2f_d). Equivalent.
- Reset: fo_pq / b2w_q have no reset. During reset fdl / cdl / b2f_n are 0, so they track pt[0] / pt[b2f_pi[0]]
  while the clock runs. Only an async reset pulse with no clock edge leaves fo_pq stale, and every use of fo_p is
  gated by fvg (fo.v) or by fdl[D + 8].v (fsa_q / fsg_q), and b2w by b2f_n != 0, so not observable. No bug found.
- Host pt writes: pt is written only on h_we && h_sel == 3 (TECH and non-TECH), the forward condition; slices match.
- New opt-in bench hooks (no default change): mutant QBT_MUT_PTRA (b2 head index misses a capture into an empty
  FIFO) and monitor QBT_PTR_CHK (registered index == fo.pi every cycle, fo_pq == pt[fo.pi] when fo.v; b2 head
  index and b2w == pt_lgw(pt[b2f_pi[0]]) whenever b2f_n != 0; event counters).

## Verdict
- A [M]: QB_TOP_PTR is cycle-exact equivalent (review + monitor + PASS 3660 / 3804; own mutant PTRA fails). No bug.
  Gap: the bench never pops a 2-entry b2 FIFO or writes pt during traffic.
- B: PTR removes the pt-mux groups. Pre-repair setup is better (-1.673 / 4 031 vs -1.761 / 5 549) and setup repair
  reaches -1.090 vs -1.358. Hold legalisation then costs 0.533 ns (d65t 0.114) and creates a new worst reg2reg
  group (u_head pcol, -1.639) [S]. **PI hypothesis not supported for area / pins**: setup repair is only ~5 k um2 in
  both runs. The inflation (+0.93-0.95 mm2) is repair_design wire buffers (~0.47 mm2) + sizing (+0.30-0.33) and does not
  change with PTR. Signal pins -1.3 % (mostly the smaller netlist: init -16 k pins); DR -3 / -6 / -6 % per iteration, still ~171 k.
- [R] Next: (1) find out why hold legal moves the u_head pcol paths (hold buffers near the head?), as in R24;
  (2) the area / pin-density lever is repair_design max transition / wire buffering (R21: 0.4 ns), not the pt mux.
