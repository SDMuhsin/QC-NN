Notes.
1. Weight rows: 3x3 conv Cout/64 x ceil(Cin/32), 1x1 sc and stem Cout/64 -> 611 rows (stem 1, stage 1 8, 2 30, 3 116,
   4 456) = 1 407 744 b stored (1 395 264 b of codes + 1x1 / stem padding). Lanes are depth-split (3 macros deep): only
   one of a lane's macros is accessed per cycle, every one of the 16 words of a cycle comes from a distinct lane.
2. Stream: 2P mapping lane = (pixel mod 4) x 8 + channel group, word = (pixel, 8 channels) x 17 b, 256 words deep;
   the 4 drain pixels x 64 channels of a cycle hit 32 distinct lanes, the write (L ~ 6 cycles later) hits a different
   address of the same lane through the separate write port (rf_2p: write wins / read X only on the same address in
   the same cycle, which the in-place schedule never produces). The 1x-capacity SP split (bank = drain row-group >> 1)
   is conflict-free only if every drain starts on a 4-cycle phase and L = 2 mod 4; tile-parity banking would need
   L = 4 mod 8 (pad 6 -> 12 cycles = 26 kb of extra delay flops) or 2x capacity (4.34 mm2).
3. Binary maps: c1 of block i+1 reads B1 while c2 of block i writes B1 (and c1 writes B2 while c2 reads it), so each map
   needs a read and a write port per cycle -> rf_2p (0.203) beats the conditional SP split (0.210).
   Block 6: HQ (128 kb) and Z (64 kb) are live together (c1 writes Z while sc still reads HQ) = 192 kb > B1 + B2 =
   128 kb; a third 64 kb map adds 0.203 mm2 (total 7.27 mm2) unless Z goes elsewhere (S is 75 % free at block 6).
4. Params: 3 904 x 110 b at 1 channel / cycle = 64 cycles to load a 64-channel group; per-tile pass switching (v1.1
   interleaved schedule) needs either a 2-context register file of the active groups or a wider port (2 x 1952 x 110,
   0.544 mm2, 32 cycles).
5. Image: not double-buffered (loading image n+1 during image n would double it, +0.135 mm2).
