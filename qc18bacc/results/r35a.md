# R35a: pre-mortem of the R35 full-chip sign-off (6.5 ns; DR 0, antenna 0, setup / hold 0 tt + ss)
[M] measured here (tau6; r35_* read-only; probes deleted), [S] script / log / report, [E] estimate.  Chip probe = PT tt 6.5 ns
on the r35_topf CTS netlist (no SPEF), r35_colb ETM, r22_r34_B hub db, act black box, pt_top_sdc.tcl, TOPL 0.  By severity.

## 1. Hub inputs are unbuffered: col -> hub abutted interface and the hub ETM are out of range (setup AND hold fail)
* Evidence: 5 790 of 6 615 hub ETM input pins have capacitance > 65 fF (max 333 fF) [M]; column ETM outputs have
  max_capacitance ~65 fF [M].  OR cts.drv: ~2 800 column f_y outputs at 0.1-0.3 pF [S].  Slew at hub pins 1.0-1.25 ns vs
  ETM index max 0.385 -> PT extrapolates: hold time 186 ns (slack -183.3 ns, f_y[436] -> wb_fy_3564_), setup time -106 ns
  (slack -103.1 ns, b2[11] -> u_top_n36620) [M chip probe].  COL -> hub: 386 hold endpoints < -1 ns (151 < -5 ns), 85
  setup endpoints < 0 (55 < -2 ns) [M].  The tables are also bad at realistic slews (<= 0.2 ns): hub tt 114 setup arcs
  < -5 ns (to -15.0 ns, optimistic) and 78 hold arcs > 5 ns; ss 198 < -7 ns (to -30 ns) and 176 > 7 ns (to 132 ns) [M].
  The artefact pins are the high-cap ones (151-197 fF) [M].  hubfix (OR .lib only) still has 69 / 51 arcs beyond +-3 ns,
  and PT links the unfixed r22_r34_B .db [M].
* Impact: chip PT hold and setup fail at any period; abutted pins have no top wire, so nothing at the top can fix it.
* Fix: buffer every hub input at its pin inside the hub (buffer_ports -inputs or a BUFFD2/4 at the pin), re-extract ETMs;
  make the column output budget load = real hub pin cap; gate ETM acceptance on a +-(L+1) ns constraint-range scan.

## 2. The act block is not connected to the chip power grid, and the grid check cannot see it
* Evidence: top PDN over u_act_blk has 0 via7 (M7-M8), only M8 / M9 straps + via8 (374 / 368) [M]; act view used by the
  top (act_early.lef / qb_act2_blk.lef) has 0 PG pins [M], while the act db has VDD / VSS bterms with M7 straps [M].
  check_power_grid on r35_topf pdn.odb: "PSM-0014 Number of voltage sources cannot be 0" for VDD and VSS [M], so the
  flow's pdn check never runs (summary.txt only shows "error: PSM-0014").
* Impact: act unpowered in the merged chip (LVS / IR fail); "resume top from cts" keeps this PDN.  Fix: redo the top from
  floorplan/pdn with the final act abstract (PG pins); give check_power_grid a source (PG pins / vsrc) and fail on error.

## 3. Top built on stale exact-shape M7-M9 abstracts of blocks that were re-routed
* Evidence: ring LEFs keep exact M7 / M8 / M9 shapes (impl/r5b/lef_ring.py).  Top uses r5b_blk column (Nov 14) and
  r22_r34_B hub views [S kit.env MACRO_LEFS]; blocks are r35_colb and r35_hubB (re-routed from cts_rt).  Top PG wires over
  column 3 hit 0 shapes of the r5b ring LEF but 533 M7 shapes of r35_colb's LEF [M] (~4 000 over 8 columns [E]).
* Impact: shorts in the merged GDS that top DRT cannot see (it checks against the old OBS); same for top signal wires
  in M7-M9 gaps and over the hub once r35_hubB is re-routed [E].
* Fix: regenerate the top views (lef_ring.py on the final block LEFs) before the top floorplan; or a contract: blocks keep
  M7 solid OBS except PG straps, top uses M8 / M9 only over blocks.

## 4. 1 088 hub outputs drive 3-mm dont_touch M8 trunks with no buffer
* Evidence: split14 puts no launch buffer when the driver is a seam block pin; trunks are dont_touch [S split14.tcl].
  OR cts: u_hub/u_top_g_r3b_t2_s[*] load 0.71 pF vs limit 0.066 (1 088 pins), s_q 225 pins > 0.3 pF [S].  On M8 the trunk
  is ~1.1 pF (0.34 fF/um, rc/tt.tcl) [E] -> ETM slew ~6 ns, clk->Q +3 ns by extrapolation [E].  Chip probe: 5 850
  max_cap / 14 315 max_transition violators even without wire RC [M].
* Impact: max_transition fails; t2 setup into the column north pins likely fails [E].  Fix: strong output buffers at
  those hub pins (inside the hub), or drop dont_touch + an L buffer in the hub's north rows.

## 5. Top post-GRT repair fixes hold against the artefact arcs by default
* Evidence: impl/r35/shim/post_grt.tcl runs repair_timing -hold unless QB35_GRTHOLD=0 (default 1) [S]; pc_setup_only.tcl
  disables hold repair for exactly this reason [S].  OR postcts: 19 621 hold endpoints, WNS -24.2 ns [S summary.txt].
* Impact: up to 10 % of instances as hold buffers on the top (max_buffer_percent 10) [E]: area, congestion, setup loss.
* Fix: default QB35_GRTHOLD 0 until item 1 is fixed; then hold-fix only paths whose arcs are in table range.

## 6. Top ss corner is signed off without parasitics; the top SPEF lacks the R31 fix
* Evidence: r35_topf kit.env CORNERS="tt", rc/ has tt only [M]; tdr (impl/r8 dr) writes SPEF for $CORNERS only, and
  tpt reads out/qb_chip_ss_pt.spef [S].  tdr does not set QC_SPEF_UNESC=1 (default 0 in def2spef.py) [S].
* Impact: PT ss with no SPEF (zero wire load, optimistic); escaped CTS nets lose *CONN (R31 PARA-044).  Fix: after tdr run impl/pnr/run.sh spef with QB_SPEF_CORNERS="tt ss" QC_SPEF_UNESC=1; make tpt fail on not_annotated > 0.

## 7. Top clock balancing uses default block insertion delays
* Evidence: clk14 / bal14 / post_grt14 use QB14_HINS 0.90, QB14_AINS 0.55, QB11_INS 0.96 unless set; run35.sh sets none
  [S].  Measured: hub QB_IO_LAT 1.412 (r35_hubB r34_L.txt; R32 PT 1.70), act 0.77, column PT L 1.035 tt (max 1.23), 1.57 ss
  (max 1.90) [S].  Hub sinks 0.5-0.8 ns later than balanced [E].
* Impact: skew on 21k abutted col <-> hub and 4.6k act <-> col nets, which cannot get top hold buffers.  Fix: set the
  three knobs from the final block PT latencies before tpnr.

## 8. Chip IO constraints: QB35_TOPL defaults to 0 and the OR top SDC is unshifted
* Evidence: chip probe (TOPL 0): hold violators from rst_n 1 488 (removal/hold), h_go 1 502, h_data 144 [M]; OR postcts
  rst_n -> u_hub removal -4.27 ns [S pc1_hold.rpt]; effective clock arrival ~6.5 ns = one period [S clk14.txt].
* Fix: one IO latency L for OR (top_sdc) and PT from the routed tree; rst_n as a synchronised / false-path reset.

## 9. The hub route step runs at 2.8 ns, not 6.5 ns
* Evidence: "R34_STEP rt r35_hubB 6.5" but db/cts_rt.sdc create_clock -period 2.8 and "IO budget re-applied (P 2.800000
  L 1.412)"; hold repair then sees 38 285 endpoints (margin 0.15) [S r35_hubB/openroad.out].
* Impact: setup / hold repair against the 2.8-ns budget (input min delay 0.14 vs 0.325 + L): extra buffers, DR risk.
* Fix: in rt, re-create the clock at QB9_PER and qb5_io_apply P L before the post-GRT repairs.

## 10. Top-level antenna check is vacuous at block pins
* Evidence: 0 ANTENNA* statements in the hub, act and column abstracts [M]; 3 745 block-to-block nets are top-routed
  (1 090 col <-> hub t2 trunks over 3.1 mm of M8, 2 655 act <-> hub) [M].
* Impact: "antenna 0" at the top proves nothing for those nets (M9 has no diff-PWL, R29).  Fix: add ANTENNAGATEAREA / ANTENNADIFFAREA to abstract pins from the block dbs, or a flat antenna run.
