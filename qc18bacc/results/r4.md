## 1. RTL prepared for synthesis (behaviour preserved)

All changes are new files or default-off hooks.  The default builds are unchanged.  Outside qc18bacc:
`flow/tsmc65/syn/dc.tcl` and `run_dc.sh` gained an optional `QC_POST_HOOK` (DC `saif_map` write).  A whole-chip DC
of the flop variant (`impl/r4/qb_chip_tech_flops.f`) was started too, and stopped after 1.3 h to free CPU.  The
macro-vs-flops decision below therefore rests on the standalone `qb_seq` runs.

| item | what | where |

**Macro vs flops for the program memories [S]** (standalone `qb_seq`, DC topo tt 1.65 ns, same recipe):
flops (DSCM 0) **0.940 mm2**, macros (DSCM 1) **0.737 mm2** incl. 2 x 0.118 mm2 macros: **-0.204 mm2**.  A macro
for the load-permission table would need 4 copies (2 reads per context per cycle) = 4 x 0.030 mm2 (rf_sp 288 x 42 m4)
against ~0.1 mm2 of flops + muxes [E]: no gain, kept as flops.  Stamps are written every commit and read 6 times per
cycle: flops.

**Benches (all PASS) [M]**
* Tech RTL (`QBT_TECH=1`, macro pin models `hw/tech/qb_mem_arm_beh.sv`), streamed: E6_s0 val 0..4 and E6_s1 val
  7 / 42 / 88: logits 100 / 100, `export_top3.py --check` torch.equal PASS on all 8, 600 / 600 tiles cycle-exact,
  intervals = R3c (3 748 / 3 788 / 3 812 / 3 804 ...), err 0.
* Default RTL after the rename: `run_tb_chip.sh` val 0 / 1 / 2 PASS; `run_tb_top.sh` R3a img0 and R3B s0 img0
  PASS (3 748 cycles, 633 664 checks).
* Gate level (VCS zero delay, compiler macro models, DC netlist): see section 3.

**Token path (r3b open item 1).**  It is critical: 239 MHz tt.  It is still not the worst path; the
load-permission chain of the same sequencer is (section 2).  The retiming needs a re-synthesis of the chip (2.2 h),
which did not fit after the DC run, so it is open (section 4).

Hold: tt worst -0.033 ns (72 endpoints), pre-CTS.

**Two findings.**
1. **The R3b sequencer is the chip's critical path [S].**  Its combinational load-permission chain (table read at
   `lptr` -> (j - lb + 1) x words multiply -> compare -> `cur` -> second table read -> stamp lookup + add + compare ->
   `l_ok` -> the loader in `qb_act2`) and the token chain (r3b.md item 1) were never synthesized before R4 and limit
   the chip to 170 MHz tt / 105 MHz ss.  The array and lanes are at 400-670 MHz tt in the same netlist.
2. **The DC run was handicapped by a constraint artifact.**  The ARM rf_2p `.lib` checks CLKB against CLKA.  Both
   port clocks come through their own ICG, so pre-CTS this check becomes a clock-as-data path from the clk port:
   72 ns of unbuffered port delay.  DC saw WNS -369.5 ns for the whole compile (TNS -61 k, 49 k violating paths).  PT
   uses `impl/r4/constraints.sdc`, which makes these 40 macro clock pins false paths.  DC did not: its delay
   optimisation chased an unfixable worst path.  This is the likely reason why the core classes reach 400-480 MHz
   here against 600 MHz for the same column in pnr_slice2 [E, not separated].  Re-running DC with the fixed SDC takes
   2.2 h and did not fit the time box.

## 3. Power

**Method.**
* **Activity: gate-level [M].**  VCS zero-delay simulation of the DC netlist (`impl/r4/gls.sh`: compiler Verilog
  models of the macros, cell models, `+nospecify +notimingcheck`) running the chip bench (`tb_qb_chip.sv`
  `+define+QBT_GLS+QBT_VSAIF`).  The bench loads the program, then streams E6_s0 val 0 / 1 / 2 back to back.
  * Logits: 100 / 100 on all three images, bit-exact against IntBin2.
  * Intervals: 3 748 / 3 788 cycles, identical to RTL and model + 1; err 0.
  * Run cost: compile 5 min, simulation 24 min, 4.3 GB.
  * The bench's tile-end loop was not yet disabled under `QBT_GLS`, so the log has 3 harmless `CYCLE_MISMATCH ... rtl
    ce -1` lines (no taps in a netlist).  That loop has since been guarded and re-checked on RTL (PASS).
* **Window [M].**  The SAIF is the steady-state image interval [go of image 1, go of image 2), 3 788 cycles.  It holds
  the engine on val 1, the head (pool tail + FC) of val 0, and the IMG load of val 2, so it is one repeating interval
  of the stream.  PT annotation: 100 % of nets.
* **Power [S + M].**  PTPX tt (1.0 V, 25 C), averaged mode, DC topographical SPEF, ideal clock (pre-CTS: ICGs and
  flop clock pins, no tree).  The SAIF is rescaled per clock period with the same toggles per cycle (`impl/r4/pwr.sh`).
* **Macros [S + M].**  The ARM `.lib` has zero CLK access energy, so the access energy comes from the datatable at tt:
  (reads x E_read + writes x E_write) over the window, plus standby leakage (`power.py`).  Reads and writes are
  counted per macro type from the RTL SAIF of the same window (`macro_counts.py`); RTL and gates are cycle-identical.
  PT's own macro power (pins + ICG, group "memory", 0.18 W at 400 MHz) is added on top.  That may double-count the
  input-pin share of the datatable current, so the macro line has a range: datatable only 4.15 uJ / image.
* **Ops [S].**  Executed ops = 2 x 119 873 024 executed MACs per image (`workload.py`, E6_s0; static: nonzero QC
  terms x positions) = **239.7 Mop / image**.  Head FC MACs are not counted.

**Caveats [E].**
* Zero-delay activity has no glitches.  qc18acc measured SDF / zero-delay = 1.34 on its array.
* No clock tree.  qc18acc post-route power was 1.65 x pre-route.
* Pre-route parasitics (DC topographical).
* So 24.6 uJ / 9.8 TOPS/W is a pre-layout figure, likely optimistic by 1.3-1.7 x.

**RTL-SAIF path (not used).**  A Verilator SAIF of the same window was built (`saif_window.py`, two runs subtracted,
because Verilator ignores `$dumpoff`; `saif_fix.py` for header / generate names; DC `saif_map`).  PrimeTime still
annotated 0 nets: PSW-130, a syntax error on the Verilator SAIF.  The gate-level route made it unnecessary.

## 4. Open items

1. **Retime `qb_seq` (chip critical path, 170 / 105 MHz tt / ss).**
   * Load permission: precompute `epos` / `adv` one cycle ahead.  Prefetch `lt[lptr + 1]` like the descriptor FIFO.
     Register the per-entry stamp-ready.
   * Token: evaluate the start condition one cycle ahead (r3b item 1).
   * Without these the array (400-670 MHz in this netlist) idles behind its own sequencer.
2. **Re-run whole-chip DC with `impl/r4/constraints.sdc`** (rf_2p CLKA / CLKB false paths): about 2.2 h, 15 GB.
   Expected: the core classes return toward the slice's 600 MHz [E].  Also lower the clock power: 54 % of the flops
   are ungated (delay lines).
3. Pipeline the head FC adder tree (314 MHz tt) and the qb_top `f_pg3` -> lane `s_rd` routing (402 MHz).
4. **Disk on the tau hosts.**  The shared `/tmp` was 100 % full on both hosts.  DC's reports were lost and
   regenerated from the .ddc (`impl/r4/dc_rpt.tcl`).  Old P&R probe directories (`qbc_p1`, `qcs2_a`, `qcs2_b`,
   `qbs_p1`) were deleted to continue.
5. Post-route power (clock tree, glitches via SDF) and P&R of the whole chip are not done.
