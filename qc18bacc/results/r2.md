# R2: activation supply `qb_act` (ARCH v1.2 RTL plan R2)

RTL: `hw/rtl/qb_act.sv` (loader, line buffer `qba_lb`, sequencer, pipelines) + `hw/rtl/qb_act_net.sv` (patch network
`qba_s1` / `qba_s2` and skip flags `qba_flg`, generated by `hw/tb/gen_act.py`). Layout helper: `compile/layout.py`
(new; imports nothing of the existing packages, `compile/test_compile.py` ALL PASS after the change [M]). Bench:
`hw/tb/export_act.py` (vectors from `compile/dataflow.py`, golden p2, cross-checked against `export_core.py`'s
stimulus), `hw/tb/tb_qb_act.sv`, `hw/tb/run_tb_act.sh`. Synthesis: `impl/run.sh all qb_act 2.0` (same DC / PT flow and
settings as r1.md), groups by `impl/act_summary.py`. Raw lines: `results/r2_tb.txt`, `results/r2_runs.txt`.
Labels: [M] measured (RTL simulation / test), [S] synthesis (DC + PT, pre-route), [E] estimate.

## Structure

```
 map macros (rf_2p 128x128 x4, 1-cycle read)        qb_act
 m_ren/m_ra (regs) --> macro --> m_q --> rdq (512 b reg) --> line buffer LB: 8 slots x 2048 b (16 384 flops)
                                                              | shift 1/2/4 slots + 1 quarter-row write / cycle
                     sel1 (one-hot, reg) --> S1 chunk slice (192 x 32 b regs): dynamic chunk mux
                     sel2 (one-hot cfg, reg) --> S2 = act register (16 x 288 b): static per-cfg mux / zero padding
                                             --> ACT_PIPE (1) register stage --> act port of qb_core
             LB --> 512 group ORs (regs) --> per-(cfg, chunk) zero flags --> int8 item mask (skip)
 sequencer: tiles x channel tiles x [planes x] chunks --> item descriptor d_* (first, eot, plane, neg, stem, g3n, chunk, ct, tile)
```

* **Line buffer**: 8 row slots of 2048 b (every map row of E6 is 2048 b: W x C = 32 x 64, 16 x 128, 8 x 256, 4 x 512;
  image 32 px x 8 planes x 8 ch). Slot s = window row s (window base = first input row of the tile, incl. a zero pad
  row). Advancing the window = shift by 1 / 2 / 4 slots (5:1 mux per flop: hold, +1, +2, +4, write); the loader writes
  one 512-b quarter-row per cycle into the slot `row - vb` (post-shift coordinates) while the current window is in use
  (prefetch of up to 8 - K rows). Pad rows (3x3, iy = -1 / H) are written as zero lines (no macro read); odd rows of
  1x1 stride-2 passes are not loaded.
* **Patch network** (two registered stages, 32-b groups throughout):
  S1 group (slot, x) <- LB group (slot, g W + x) for the item's chunk g (3x3), or a static stride-2 1x1 gather
  (slot, t W/2 + x_in/2) <- LB group (slot, t W + x_in) (all channels of the centre pixel, 1x1 groups j = channels 8j..).
  S2 act unit (row r, tap t) <- the S1 group of input (iy, ix) for the pass configuration, or zero (column padding,
  out-of-map rows of whole-map tiles). 11 configurations (gen_act.py table): W32 s1 (2 tile phases: x 0-15 / 16-31),
  W32 s2, W32 1x1 s2, W16 s1, W16 s2, W16 1x1 s2, W8 s1, W8 s2, W8 1x1 s2, W4 s1.
* **Stem**: the image is stored as one 64-channel map (channel 8 plane + c), so stem cycle h = chunk h of a W32 s1 pass;
  qb_act emits plane = 4h, stem, g3n = (h == 1) as qb_core expects (r1.md).
* **int8 (block 6)**: per (channel tile, plane) block the plane's rows are loaded (HQ: 8 rows, Z: 4 rows with the next
  plane prefetched into slots 4-7), the registered group ORs give per-chunk "patch nonzero" flags (OR over exactly the
  LB groups the act of that cfg / chunk reads = the dataflow's 16 px x 288 b patch), and only nonzero chunks are
  issued, in plane-major / chunk order. A channel tile with no executed item gets one all-zero item (first, plane 0) as
  export_core does. Plane 7 items carry neg.
* **Sequencer**: one array pass per command (cfg, nchunk, nct, ntile, int8, stem, base); binary passes issue one item per
  cycle when the window is loaded (`vdone >= vb + K`), int8 blocks wait for the window + 1 cycle (flags), then iterate.

### Mux depth (generator statistics, `gen_act.py`) [M]

| stage | candidates per bit, all cfgs | dynamic within one pass | note |
|---|---|---|---|
| LB flop input | 5 (hold, shift 1 / 2 / 4, write) | 5 | write data = the registered 512-b line (no rotation) |
| S1 (chunk) | max 17 (hist 1: 40, 2: 16, 3: 32, 4: 16, 5: 24, 8: 26, 9: 22, 16: 10, 17: 6 groups) | W32 2:1, W16 4:1, W8 8:1, W4 16:1; 1x1 1:1 | AND-OR on one-hot sel1, registered on both sides |
| S2 (act) | max 10 + zero (hist 2-10, median 7) | **1 (static per pass / tile phase)** | one-hot cfg, registered on both sides |
| skip flags | OR of 16 / 64 / 128 group ORs (512 b / 2 kb / 4 kb) | - | group ORs registered |

The ARCH target "~4:1 per patch bit per configuration" holds for the act stage (static) and for S1 at W >= 16; the
chunk select at W8 (8:1) and W4 (16:1) is the price of not rotating the line buffer (rotation conflicts with the
int8 skip, which jumps over chunks); both sides of it are registered, so it is a 2-level MUX4 tree per bit.

## Map layout (contract with the compiler and R3) — `compile/layout.py`

* Row = (plane, y) of a map, 2048 b = 4 *lines* (512 b = the 4 macro words of one address, macro m = line bits
  128m..128m+127). `row = plane * H + y`, `line = base + 4 row + (pos >> 9)`, chunk-major inside the row:
  `pos = (c >> 5) * 32 W + 32 x + (c & 31)` (chunk g = channels 32g..32g+31 of all W pixels, contiguous).
* B1 / B2 (binary maps) <= 128 lines, Z 128 lines (8 planes x 4 rows), HQ 256 lines (8 planes x 8 rows: two maps,
  address bit 7 = map), IMG 128 lines as a 64-channel map (channel 8 plane + c).
* `to_lines` / `from_lines` / `addr` convert dataflow entries <-> lines (self-test: round trip of 5 geometries + 800 random entries vs `addr`
  [M]); `export_act.py` loads exactly `to_lines(source buffer before the pass)` into the bench's macros.

## Contracts for R3

1. **Command / done**: one array pass per `start` (cfg 0, 2..10, nchunk, nct, ntile, int8, stem, base); `busy` while
   running, `done` 1-cycle pulse after the last act word. Interleaving tiles of two passes (v1.1 list scheduler: c1 of
   block i+1 with c2 of block i) needs a second qb_act context or tile-granular commands with a window reload (see
   deviations).
2. **Item timing**: descriptor `d_*` valid one cycle after the issue decision, act 2 + ACT_PIPE (= 3) cycles after
   `d_*`; qb_core wants codes / ctl one cycle before the act, so R3 has 2 cycles from `d_chunk / d_ct / d_plane` to the
   code port (weight macro read + boundary register). `d_eot` marks the end of a (tile, channel tile): on the last
   item for binary passes, alone (d_vld = 0) or on the zero item for int8 passes -> R3 issues the capture / cmp then.
   `d_first` = first item of a (tile, channel tile) (qb_core `first`). Fields of d_* map 1:1 to qb_core ctl
   {plane, neg, stem, g3n, first, valid}.
3. **Map read port**: qb_act owns the read port of the source map during a pass (m_ren / m_ra registered, 9-b line
   address, bit 7 = second map for HQ). Read latency: m_ra register -> macro -> rdq register -> LB write = line usable
   4 cycles after issue.
4. **Writers** (b2 capture, b1_next drain, hq jobs, z) write the same layout. Per (16-px tile, 64-ch channel tile):
   W32 / W16 = 2 full lines, W8 = 4 half lines, W4 = 8 macro words. Note: a fused drain cycle (4 px x 64 ch of b1_next)
   at W32 hits the same macro (index x / 4) for both 32-ch chunks -> one write-port conflict per cycle; needs a one-tile
   write buffer (1 kb) or a macro swizzle (R3 decision) [E].
5. Bandwidth (one 512-b port, measured below): binary passes run at one item per cycle except b2.c1, b2.sc, b4.sc
   (2 rows per 4 / 2 / 4 items = 2x the port) and the first window of each pass; block 6 is far from rate (next section).

## Bench (Verilator 5.050): PASS, 0 mismatches [M]

Per image, every array pass (20: stem, b0-b5 c1 / sc / c2, b6 c1 / sc / c2, b7 c1 / c2) runs standalone: map macros
loaded with the dataflow source buffer before the pass (layout.py), qb_act started with the pass command, and every
act-port item (4608-b act + first / plane / neg / stem / g3n / chunk / ct / tile) and every end-of-tile marker is
compared in order with `export_act.py`'s list, which is asserted identical (ctl + act of every item) to the item
stream of `export_core.py`'s qb_core stimulus (`img0: 2880 items == export_core stim items: PASS`, img1 2920).

**Block 6 cannot be fed at array rate by the ARCH line buffer [M].** Its int8 tiles are the whole map, and every
one of the 8 channel tiles needs all 8 planes of the input again (plane-major items per tile, one accumulator set per
PE), so the working set per channel tile is the whole HQ (128 kb, b6.c1 / sc) or Z (64 kb, b6.c2), not "the rows of
one plane" (ARCH: "~12 kb"). With one 512-b port the passes cost 2 774 + 1 718 + 1 212 = 5 704 cycles vs 1 040 items
(dataflow schedule attributes 370 + 46 + 904 = 1 320 cycles, cycles.md p2): **+~4 400 cycles / image (~2.3x the
3 371-cycle image)** if built as is. Options for the PI [E] (array cycles of b6 c1 + sc + c2, img0 items 336 / 48 / 656):

| option | b6 array cycles [E] | cost |
|---|---|---|
| as built (LB per plane, 512 b / cycle) | 5 704 [M] | none |
| int8 maps slice-major ((plane, chunk) contiguous), writer-side (plane, chunk) zero flags, read only executed slices, 512 b / cycle; sc from a decimated (even-pixel) HQ copy | 336 x 4 + 656 x 1 + 48 x 8 = 2 384 | layout change, 32 kb extra map, writer flags |
| same at 1 024 b / cycle (HQ striped over B1 + B2; both idle in block 6) | 672 + 656 + 192 = 1 520 | + a second read port into qb_act (512 b) |

| register store of HQ + Z (192 kb) | at rate | ~1 mm2 of flops [E] — not viable |

## Synthesis (tt compile, 2.0 ns)

`qb_act` (ACT_PIPE 1), tt compile 2.0 ns (tau1, DC wall 10 min): **0.435 mm2** [S], 125.8 k cells, 33 057 flops,
302 kGE; DC WNS 0.

| group | flops | um2 total | comb (mux / OR) | seq (flops) | % |
|---|---|---|---|---|---|
| line buffer `qba_lb` (8 x 2048 b, 5:1 shift / write mux) | 16 384 | 208 482 | 93 098 | 112 067 | 47.9 |
| S1 chunk slice `qba_s1` (regs + dynamic chunk mux) | 6 144 | 99 401 | 57 376 | 42 025 | 22.8 |
| S2 patch network `qba_s2` (act regs + static cfg mux, zero pad) | 4 608 | 70 483 | 38 965 | 31 519 | 16.2 |
| act output pipe (ACT_PIPE = 1, fanout to the 8 PE columns) | 4 608 | 31 519 | 0 | 31 519 | 7.2 |
| skip detect `qba_flg` (512 group ORs + 25 flags) | 512 | 17 965 | 14 463 | 3 502 | 4.1 |
| control (loader, 512-b macro input register rdq, sequencer, descriptors) | ~800 | 7 459 | 1 610 | 5 791 | 1.7 |
| **total** | 33 057 | **435 309** | | | |

Patch muxes (S1 + S2 comb) = 96 k um2 [S]; flops = 6.8 um2 / bit including clock gating [S]. Against the core
(5.353 mm2, r1.md) qb_act is +8.1 %; ARCH's ~12 kb line buffer implied ~0.1 mm2 [E].

Timing (PT, pre-CTS ideal clock): **tt 501.8 MHz** (meets 500; DC recovers area until every path just meets, tt path =
command input c_cfg -> sel1 register, i.e. the 20 % input-delay budget, quasi-static in practice), **ss 334.1 MHz**
(WNS -0.99 ns) [S]. ss critical path: sel1 register (W8 chunk-0 select line) -> buffer tree (fanout 2 048 AND gates,
~0.8 ns) -> AND-OR chunk mux -> S1 register (2.74 ns). qb_act is not the chip's ss limiter (core: 314.9 MHz, wide lane);
replicating sel1 per LB slot would shorten the tree if needed. v0 (shift select decoded from vb - vbp at the LB, 16 k
flop fanout) was 321.1 MHz ss / 0.431 mm2 (`r2_runs.txt`); the final RTL registers the one-hot shift (shq).

## Deviations from ARCH v1.2 and why

1. **Line buffer 16 kb + 6 kb S1 + 4.6 kb act (+ 4.6 kb output pipe)** instead of "~12 kb": 8 row slots are needed by
   b6.c1 (8 rows of one plane) and by b4.c1 (5-row window + 3 prefetch rows); S1 and the act register keep every patch
   bit behind at most one dynamic (chunk) and one static (cfg) mux stage.
2. **Chunk-major row layout** (not pixel-major "one word = (pixel, 32 channels)"): a chunk of a row is contiguous, so
   the chunk select is a plain group mux and a binary tile's writes are whole lines / half lines / macro words.
3. **Image stored as a 64-channel map** (channel 8 plane + c): the stem needs no special path (= W32 s1, 2 chunks).
4. **Skip decision from the line buffer, per (tile, plane) block** (group ORs + per-chunk flags), not "1-cycle
   look-ahead on the patch": a look-ahead cannot skip runs of zero items (planes 6-7 are 2 x nchunk consecutive skips)
   without bubbles. Exact by construction: a flag ORs exactly the LB groups the act of that chunk copies.
5. **Pass-level command** (one context): the v1.1 interleaved schedule needs two contexts (2 x line buffer +
   S1, ~ +0.3 mm2 [E]) or a window reload per tile switch (R3 decision).
6. **Block 6 is port-bound** (section above): ARCH's line-buffer sizing assumed one plane per tile; the PI needs to pick
   a block-6 supply option before R3.
7. **Descriptor master**: qb_act generates the item sequence (and the skip) and hands R3 the descriptor 3 cycles ahead
   of the act; R3 derives the weight address from it (codes must reach qb_core 1 cycle before the act).
