## 1. Act hold step: RSZ-0050 "Max utilization reached" (item 1)
**Cause [S + M]: two things together.**
1. **Our flow: the hold step's db still holds every filler when the repair runs, and the resizer counts them as design
   area.**  `Resizer::initDesignArea` (Resizer.cc:2540) skips only `dbMaster::isFiller()` = CORE_SPACER masters.  The kit's
   FILL* and DCAP* masters are CLASS CORE, and repair/hold_eco.tcl removed the FILLER_* instances only after the repair.
   r48_act db/finish.odb (probe p_area.tcl, read_db only) [M]:

   | | instances | area um2 | % of core (1 742 976 um2) |
   |---|---|---|---|
   | cells | 257 491 | 1 105 011 | 63.40 |
   | FILLER_* (DCAP + FILL, all CLASS CORE) | 313 059 | 637 965 | 36.60 |
   | resizer design area | | 1 742 976 | **100.00** |
   | CORE_SPACER | 0 | | |
2. **OpenROAD: the -max_utilization cap is off in the first resizer command of a process.**  repair_timing / repair_design
   (Resizer.tcl:436 / 330) call `rsz::set_max_utilization` -> `max_area_ = coreArea() * util` (Resizer.cc:1488) BEFORE
   `resizePreamble() -> init() -> initBlock()` sets `core_` (Resizer.cc:233-250).  In a fresh process `core_` is empty, so
   `max_area_ = 0` and `overMaxArea()` (= `max_area_ && design_area_ >= max_area_`) is false: no cap.  From the second
   resizer command on, the cap is live.
   * R48 act try 4 (hold repair = first resizer command): utilization 100 %, cap 95 % not live -> 2 791 hold buffers.
   * R49 replay / current order (qb_drv's repair_design first, then repair_timing -hold -max_utilization 95): cap live,
     design area 100 % >= 95 % -> the hold loop (RepairHold.cc:270-275) never starts, RSZ-0064, then RSZ-0050 (RepairHold.cc:311).
   So the R48 reorder did not change the area; it made the cap live.  (Every flow -max_utilization in a first resizer call,
   e.g. post-CTS repair_design, has been inert: new OpenROAD bug, sec. 5.)
**Fix (in place):** repair/hold_eco.tcl removes the FILLER_* instances right after loading, before any change (PT ECO
file, hook, DRV / hold repair; they are re-placed after legalisation as before), so the resizer sees the real cells; it
logs `R35_HOLD resizer utilization`.  The 95 % cap (QB35_MAXU) is unchanged.
**Result [M]** (act hold step, dry run and the production run, same numbers): resizer utilization 0.6446 after the DRV
repair (cap 0.95); repair_timing -hold: 765 endpoints within the 0.05 margin -> 615 hold buffers, no RSZ-0050; after the
repair (unlegalised) hold wns tt +0.014 / ss +0.060, 0 violating endpoints at both corners.

### 3c. Source fix for the SRAM-pin min-step markers: outward planar access points (R50 handover, item 3)
* **Test vehicle [M]** (probe, not flow: tau5 /tmp/ckp908/r50/mini, run dirs $B/pnr/r50_mini / r50_mini2): one
  qb_p_240x144m2 (u_prm master), MX like the hub, 144 Q + 144 D nets to BUFFD1s above it, hub.cfg LEFs / layers M2-M9,
  route/drc_rules.tcl, GRT + DRT 64 iterations.  Reproduces the hub row: **DRT 20 markers, all in the pin row (M3 Min
  Step 12, notch Metal Spacing 8)**; Calibre (kit deck, block switches, window x 20-460 / y 130-136, SRAM abstract
  merged as in sec. 3) in the row y 132.3-133.0: **G.4:M3i 24, M3.S.1 8**; SRAM excluded: M3.A.1 122.
* **Mechanism, refined [M + S]:** the failing pins are not reached by vias.  The SRAM has VIA2 OBS over the pins and
  FlexPA gives each Q / D pin planar access points.  Where an M2 / M4-track x falls inside the pin narrowed by half a
  wire (a 0.06 um window) the point sits there with NORTH access (out of the macro) and the 0.10 um wire leaves the
  pin cleanly (D[10]: point at the pin centre x, wire M3 north).  Where none does, FlexPA takes an EncOpt / Center
  point near the pin edge with EAST / WEST access (D[11]: point 0.03 um from the right edge, EAST): DR leaves sideways
  on M3 and turns north 0.035 um past the pin edge -> a 0.035 um notch at the pin top = Min Step + notch spacing; DR
  never finds a clean alternative because every point of that pin has the same access.
* **Fix (new, opt-in): route/macro_pin_ap.tcl `qb_macro_pin_ap`.**  After `pin_access`, every stored access point of a
  small (< 0.2 um) signal pin of a CLASS BLOCK master is moved to the pin centre with planar access only toward the
  nearest instance edge (out of the macro), no via access; points below the min routing layer move to it (M1 -> M2);
  NearbyGrid points (off the pin) lose all access.  `detailed_route -no_pin_access` then reads the points from the db.
  No LEF, pin-shape, rule, iteration or blockage change.
  - DRT keeps the design of a `pin_access` call in memory (TritonRoute::initDesign returns early), so an edit followed
    by detailed_route in the same process is ignored (measured: identical 20 markers).  The edited db must be routed by
    a new process: route/dr.tcl + dr.sh QB50_MPA=1 run pass pa (grt, antenna repair, fillers, pin_access, edit, save
    db/grt_mpa) then pass dr (-no_pin_access).  **Run on the mini as a flow run dir ($B/pnr/r50_mini3, hub.cfg, db/grt
    from GRT) [M]: pass pa QB50_MPA 288 / 1 176, pass dr no pin access re-run, fillers 1 705, DR 173 / 154 / 0 -> 0.**
    The hold ECO path (repair/hold_eco.tcl + hold_eco.sh) got the same split: QB50_MPA=1 ends the first process after
    GRT with pin_access + edit + db/hold_mpa, hold_eco.sh runs QB50_MPA_PASS=dr (r35_hold_dr.log; h35_dr = the old DR /
    save tail as a proc).  **Run on copies of the mini run dir (hold_eco.sh, QB35_HDB finish, forced re-route) [M]:
    QB50_MPA 0: DR 21 markers (the pin-row ones), the refactored default path saves route_dr / route / finish as

## 5. New bugs / findings
* [S, M] OpenROAD: `detailed_route` after `pin_access` in the same process reuses pin_access's in-memory design
  (TritonRoute::initDesign returns when a top block exists), so access points edited in the db in between are ignored,
  even with -no_pin_access (mini: identical 20 markers).  Edited access points need a fresh process (sec. 3c).
* [M] OpenROAD Tcl API: dbAccessPoint_create rejects every call (SWIG overload typecheck on uint); dbMPin getPinAccess /
  dbAccessPoint getVias return unwrapped vector pointers; dbAccessType is opaque; getPoint returns a list.
* [M] FlexPA macro-pin access (sec. 3c): with no track inside the half-wire-narrowed pin, the points sit at the pin edge
  with sideways access -> the min-step notch DR never cleans.  Root cause of the hub SRAM pin-row markers.
* [S, M] OpenROAD: `-max_utilization` is ignored by the first resizer command of a process (sec. 1.2).
* [M] The kit's filler (FILL*) and decap (DCAP*) masters are CLASS CORE, not CORE SPACER: OpenROAD counts them as design
  area (sec. 1.1).
* [M] r48_act_s/qb_act2_blk_pnr.sdc (named in r48_act/kit.env SDC) no longer exists on tau6; the steps run from the db
