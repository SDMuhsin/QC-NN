* DR / LVS: f1 is built on the ECO-3 hub; f2 is the only valid one.  Hub GDS from gds36 lists every std cell as "no GDS"
  (hub DEF merge problem, not investigated) -> R38 must rebuild the hub GDS.

* PT IO: chip IO timed against a virtual clock with latency L (0.2 P budgets).  f1 GRT: io->seq h_go -> seq kelt_reg -1.34 ns
  (5 ns of logic after a 0.2 P input delay) = IO constraint, will show in PT; run35-style PT uses one TOPL for tt AND ss
  (ss clock latency is larger) -> ss IO slack is mis-modelled.  rst_n is false-pathed (async reset: assumes external sync).
* PT hold: column tt ETM keeps 15 hold > 3 ns / 20 setup < -3 ns arcs after etm_fix (etmcheck) -> false violations at
  those column pins; hub hold margin +0.002 tt (R37): any top skew at the hub clk pin breaks it.  Top balancing T ~7.7 ns
  (post-GRT T 8.18 in t3): latency > P, residual group spread 0.84-0.89 ns at GRT (t3) -> hold at col<->hub / act<->col.
* PT setup: f1 GRT classes (ideal clock) all >= 0 at 6.5 except io->seq; hub->col t2 +0.64, seq->seq +0.02 [M].
