# R10a: column-local int8 write-back (opt-in `QB_WB_COL=1`, qb_top + qb_act2; default unchanged; tables `results/r10a/`)
**Why it rotated [R]:** an hm cycle = 4 px x 64 ch x 8 planes; the act reads plane-pure 2048-b words at one address, so each lane-word
was gathered from 4 columns and the cycle's 16 words (one logical lane) rotated over all 16 lanes (HQ l0 = 4 tp + k, HQD 8 ct0 + oy,
Z 8 ct0 + y).  Lower bound: a column owns 2 lanes in rows 0-1 (4 in all) but writes 8 planes / cycle, so a read-side permutation
alone cannot do it: column-locality also needs per-column buffering and HQ on all 4 rows.
**Scheme (`g_wbc`, `g_srd_col`, qb_act2 T):** HQ lane-word = one job's 16 px x 8 ch of column c, row (tp + pl) & 3 (rows 2-3 at
176 + 4 pl + ct); HQD a ct pair per 64-b write and Z 4-cycle groups, both on rows 2-3; 2 304 buffer flops / column; every write
goes to lane 8 r + c only.  Read: 8:1 lane select per slot + per-row-pair address (no rotator); qb_act2 applies a fixed transpose
T (wiring) to each S word, so line buffer, S1 / S2, flags, s_ra and the program are unchanged (no new program: the "compile option"
is the physical map `compile/layout_s.py phys_col`, self-test: producer column == lane column, collision-free, hub + T == logical,
disjoint from r / stream).  First attempt (half of HQD on rows 0-1) collided with b6.c2's r reads (s_conf err): HQD stays on rows
2-3, which are then 100 % busy during the 64 back-to-back hm cycles.
