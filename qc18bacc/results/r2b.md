# R2b: two qb_act contexts + block 6 from S (supply config C) — `qb_act2`

RTL: `hw/rtl/qb_act2.sv` (top `qb_act2`: flag store, map / S arbiters, shared S1 / S2 / act pipe; `qba2_ctx` = one
context; `qba2_lb` = its line buffer) + `hw/rtl/qb_act2_net.sv` (S1 network over both line buffers + S-word
candidates, generated by `hw/tb/gen_act2.py` from `gen_act.py`'s table); reuses `qba_s2` (qb_act_net.sv) and
`qba_areg` (qb_act.sv). R2's `qb_act` is untouched (separate top) and still passes its bench (below).
S layout + flags: `compile/layout_s.py` (new, imports `layout.py`; self-test PASS [M]). Model: `compile/supply.py`
(port arbitration made per cycle, + a per-tile replay log; cycles.py untouched; `test_compile.py` ALL PASS [M]).
Bench: `hw/tb/export_act2.py`, `hw/tb/tb_qb_act2.sv`, `hw/tb/run_tb_act2.sh`. Synthesis: `impl/run.sh all qb_act2 2.0`
(flow / settings as r1 / r2, tau1), groups by `impl/act2_summary.py`. Raw lines: `results/r2b_tb.txt`,
`results/r2b_runs.txt`. Labels: [M] measured (simulation / test), [S] synthesis (DC + PT, pre-route),
[Mod] modelled (compile/supply.py), [E] estimate.

## Structure

```
                 map port (rf_2p 4 x 128 b, 512 b)            S port (lanes 0..15 of S, 2048 b)
 ctx0 / ctx1 loaders --req/seq--> arbiter M --> m_ren/m_ra/m_ctx (regs) --> macro --> m_q --> rdq (512 b reg) --+
                      --req/seq--> arbiter S --> s_ren/s_ra/s_ctx (regs) --> S     --> s_q --> sdq (2048 b reg) -+
                                                                                                                 |
 per context c (qba2_ctx): LB_c 8 x 2048 b  <-- write (ev pipe of c): binary 1 quarter of rdq / zero, int8 slot <- sdq
                           sequencer: tokens (tgo), binary S_BIN (as R2) | int8 S_INT (flag-driven items, FIFO head)
 shared: sel1a / sel1b (one-hot, regs) --> S1 (192 x 32 b regs; AND-OR over LB_0 and LB_1) --> S2 = act (cfg mux)
         --> ACT_PIPE --> act port of qb_core ; descriptor d_* / a_* (+ ctx)
 flag store: HQ 64 + HQD 8 + Z 128 set-only flops, producer write port (f_clr / f_we / f_bank / f_idx / f_nz)
```

* **Contexts.** Two `qba2_ctx`, each with its own command register (start[c], cfg, nchunk, nct, ntile, int8, stem,
  base; both may start in one cycle), loader, 16-kb line buffer and sequencer. Binary passes run exactly R2's loader /
  window / patch logic per context; the act path is shared (both contexts never issue in one cycle: tiles are
  serialized by R3's tile tokens; `err` flags a violation, never set in the benches [M]).
* **Tile tokens.** `tgo[c]` = one pulse per scheduler tile (binary: (pixel tile, channel tile); int8: channel tile).
  A tile's first item issues at max(token, data ready); the token may arrive early (3-b counter, not reset by start).
* **Map port arbitration (shared 512-b port).** Every loader step of a context is one port cycle (quarter line, pad
  line written as zeros, skipped odd row of a 1x1 stride-2 pass), requested when the step is allowed (LB slot free,
  `l_ok[c]`). Both requesting: the context whose current tile is **older** (smaller `l_seq`, = commit order of R3's
  tile sequence) wins; per cycle, no row lock. Same rule on the S port.
* **Block 6 from S (int8 passes, cfg 8 / 9 / 10).** The line buffer becomes a FIFO of S words (head = slot 0).
  Load sequencer: per channel tile, the executed words in item order (c1: word (plane, chunk) per executed slice;
  c2: word (plane, chunk quad) if any of its 4 slices is executed; sc: both words (plane, 0 / 1) of an executed
  plane), one S word per grant while < 8 words are buffered (`lcnt - rcnt < 8`); words are re-read for every channel
  tile. Issue sequencer: executed items (plane-major, chunk order; 128-b remaining mask + priority encoder) back to
  back, when the head word(s) are written (`wdone - rcnt >= 1`, sc 2); after an item the consumed words are released
  (c1 1, sc 2, c2 1 on the last executed chunk of its quad): `rcnt` += n at issue, LB shift by n one cycle later (the
  item's S1 read sees the old head). A channel tile without executed slices issues one zero item (first, eot, plane 0,
  chunk 0) as export_core. `d_eot` always rides on the last item (no S_CTEND / S_FLAG / empty cycles of R2).
* **S1 candidates for S words** (gen_act2.py): cfg 8 S1 (iy, ix) <- slot 0 group 8 iy + ix; cfg 9 S1 (2 oy, 4 t + ox)
  <- slot t >> 2 group 16 (t & 3) + 4 oy + ox; cfg 10 S1 (iy, ix) <- slot 0 group 16 (g & 3) + 4 iy + ix (4 lines by
  chunk & 3). 39 select lines per context (R2 33 + 6). Per S1 bit: max 23 LB candidates per context (R2 17), x 2
  contexts.
* `qba_flg` (R2's LB group ORs) is gone: the skip comes from the writer-side flags.

## S layout + zero flags (contract with the writers, `compile/layout_s.py`)

S = 32 lanes x rf_2p 256 x 128 (ARCH v1.2). An S word = one address on lanes 0..15 = 2048 b (lane l = word bits
128 l ..). The block-6 int8 maps use **lanes 0..15 only, addresses 128..239** (112 words, 224 kb):

| map | read by | words | word index -> S address | bits in the word |
|---|---|---|---|---|
| HQ (8 pl x 8x8 x 256) | b6.c1 (cfg 8) | (plane, chunk g) 64 | 128 + 8 pl + g | 256 y + 32 x + (c & 31) |
| HQD (even pixels of HQ) | b6.sc (cfg 9) | (plane, half h) 16 | 192 + 2 pl + h | t = c >> 5, h = t >> 2: 512 (t & 3) + 128 oy + 32 ox + (c & 31) |
| Z (8 pl x 4x4 x 512) | b6.c2 (cfg 10) | (plane, quad g >> 2) 32 | 208 + 4 pl + (g >> 2) | 512 (g & 3) + 128 y + 32 x + (c & 31) |

* **Flags**: one per (plane, chunk) slice = OR of the slice (HQ 2048 b, HQD the plane's 4096 b, Z 512 b), which is
  exactly the dataflow's skip rule for block 6 (every 3x3 pad-1 / 1x1 stride-2 patch set covers the whole (decimated)
  slice; asserted by the bench: item streams equal export_core's). **Store**: 200 set-only flops in `qb_act2`
  (bank 0 HQ 64 = 8 pl + g, bank 1 HQD 8 = pl, bank 2 Z 128 = 16 pl + g). **Writers**: the producer of each map
  sets the flags as it writes the slice words — HQ and HQD: the b6.hm jobs (fused lanes) — Z: the b6.c1 drain (wide
  lanes) — through the port (f_we, f_bank, f_idx, f_nz = OR of the bits it writes into that slice; set-only, so a
  slice written in pieces needs no read-modify-write); f_clr clears a bank before its producer's first write (start of
  hm / b6.c1 of the image). Flags must be final 1 cycle before the consumer's first RAW ready (R3 RAW gate = l_ok /
  token): each context keeps a registered copy of its bank (word / item masks, 64 + 128 flops, refreshed every
  cycle; not latched at the pass command), so a context may start its pass before the producer finished (the bench
  writes each bank one flag / cycle, ending 2 cycles before the consumer's first RAW ready, after the context start).
* **Writers' S write port (open for R3) [E]**: hm writes 256 int8 outputs / cycle = 8 planes x 256 b. In the natural
  lane order above, the 4 px x 64 ch of a cycle land on one lane (2 y + x / 4) in 16 different words -> 16 writes to one
  lane. Needs either a per-word lane rotation (write lane = (l + 2 pl + (g & 1)) mod 16 and a 16:1 128-b rotator on
  the S -> sdq read path, ~2048 x 15 mux2 ~ 35-40 k um2 [E]) or an hm write buffer (one 8 x 8 x 64-ch tile, 32 kb) —
  R3 decision. HQD = the even-pixel outputs written a second time (extra write cycles of hm, ~1/4) [E].

### S read-port occupancy and conflicts (E6_s0 val 0 / 1, from the config-C schedule) [Mod] / [M]

| pass | S words read img0 / img1 [M] | read span (cycles) img0 | occupancy of the 2048-b port | same-cycle S drain reads of other passes |
|---|---|---|---|---|
| b6.c1 | 336 / 368 | 1995..2335 (341) | 0.99 | none |
| b6.sc | 96 / 96 | 2003..3193 (1191) | 0.08 | b6.c2 drain r reads in 34 cycles |
| b6.c2 | 176 / 184 | 2375..3254 (880) | 0.20 | b6.c2 drain r reads in 7 cycles |

The only S reads at drain time during block 6 are the b6.c2 wide-lane r reads (lo + hi, 8 lane-words / cycle in its
32-cycle drains; 224 such cycles inside the int8 read spans per image). With the int8 maps on lanes 0..15 and the
block-6 r / s stream on **lanes 16..31** (r 16 px x 512 ch x 2 x 16 b = 128 addresses of 16 lanes; s_out in place over
r), the 41 coinciding cycles per image use disjoint lane read ports: **no read-port conflict**, nothing to arbitrate
[Mod]. hm (reads s5 on all 32 lanes) finishes before b6.c1's first read (RAW on HQ); b7 has no S reads before b6.c2's
last drain. If R3 keeps the generic stream mapping (lane = (pixel mod 4) x 8 + channel group over all 32 lanes) for
block 6, those 41 cycles / image conflict and S-int8 reads must yield (r priority): +<= 41 cycles / image upper bound [E].
S write ports: Z (b6.c1 drain) on lanes 0..15, r (b6.sc) / s_out (b6.c2) on 16..31; rf_2p write ports are separate
from the read ports.

## Contracts for R3

1. **Command**: per context `start[c]` + (cfg, nchunk, nct, ntile, int8, stem, base[c]); base = map line of row 0 or
   S address of word 0 (128 HQ, 192 HQD, 208 Z). Accepted only when `busy[c]` = 0; `done[c]` pulse = last issue + 4 +
   ACT_PIPE; the next pass on that context may start the cycle after done (as supply.py: start = done + 1, loader
   active one cycle later).
2. **Tile tokens** `tgo[c]`: one per scheduler tile, in the context's tile order, at the tile's scheduled array start;
   R3 must keep tiles of the two contexts serialized on the act port (next tile's token >= previous tile's last item
   + 1), as the list scheduler does.
3. **Load gate** `l_ok[c]` + age `l_seq_c`: the context may load (rows / S words) of its current loader position
   `l_pos_c` (binary: virtual rows loaded; int8: words loaded in the pass) when the producer has written them (RAW);
   `l_seq` = R3's tile commit index of the tile owning that position (older wins both ports). The bench drives these
   from the model's per-tile RAW-ready times; R3 can drive them from its writer progress counters (any earlier
   permission only helps).
4. **Item / act timing** unchanged from R2 (d_* at issue + 1, act at issue + 3 + ACT_PIPE = descriptor + 2 + ACT_PIPE),
   plus `d_ctx` / `a_ctx` (which context = which pass; weight / param context for R3).
5. **Ports**: map: m_ren / m_ra[8:0] / m_ctx registered, m_q 1-cycle macro (R3 maps m_ctx + base to the macro set of
   that pass's source map); S: s_ren / s_ra[7:0] / s_ctx registered, 2048 b of lanes 0..15, 1-cycle read. Both:
   line / word usable by an item 4 cycles after the grant.
6. **Flags**: section above (writer port, clear, live read, 200 flops).

## Cycle agreement with supply.py

`compile/supply.py` config C was changed in one point so model and RTL agree: map-port cycles are now placed one at a
time (each line / pad line / skip its own earliest free cycle) instead of a contiguous 4-cycle row slot; with commit
order = age, this is exactly the RTL's per-cycle older-first arbiter (a younger load never displaces an older one, and
fills any free cycle). One-context configs are unchanged (A, B, D identical); C: 3 653.7 -> **3 651.7** / 3 634.9 ->
**3 632.9** cycles / image (E6_s0 / E6_s1, val[:100]) [Mod], E unchanged; supply.md regenerated. Every tile of both
images then matches cycle for cycle (no differences to explain). cycles.py defaults untouched; test_compile ALL PASS.

The cost is the second line buffer (+217 k um2, the R2 estimate for a second context was ~+0.3 mm2 [E]) and the
doubled S1 candidate set (+77 k); block 6 from S itself costs the 2048-b sdq register + LB write-data mux (~+25 k)
and saves qba_flg (-18 k). Against the core (5.353 mm2, r1.md) qb_act2 is +14 % (R2: +8 %).

Timing (PT, pre-CTS ideal clock): **tt 500.7 MHz** (meets 500: DC recovers area until every path just meets; tt path
ev2.row register -> LB write-slot decode -> line-buffer flop D), **ss 316.4 MHz** (WNS -1.16 ns) [S]. ss critical path:
`lval` (context 0 load sequencer) -> 64-b word-mask select -> 64-b priority encoder (lowest executed word) -> S
address adder (base + index) -> s_ra register (2.90 ns incl. 0.25 uncertainty). qb_act2 is not the chip's ss limiter
(core 314.9 MHz, r1.md). Iterations (`r2b_runs.txt`): v0 316.4 MHz ss (path cfg -> flag-view mux -> priority encoder
-> lct clock-gate enable), v1 registered flag views 314.1 MHz (path cfg -> K -> window-ready compare -> state),
final registered vb + K and buffered-word counters 316.4 MHz. Next steps if ss matters: Z base 224 (base | index, no
adder: all three bases then OR-able) and a registered next-word index (precomputed one cycle ahead) [E].

## Deviations

1. **Per-context command ports** (not one shared command bus): the model starts both contexts in cycle 1 of an image
   (and may start both in one cycle later); a shared bus would cost a cycle against config C.
2. **Port arbitration per cycle, older tile first** (supply.py changed to match, above) instead of whole-row slots.
3. **R3 interface additions**: tile tokens, load gate + age, loader position, flag write port, ctx on ports and
   descriptors. The bench drives them from the model (open-loop replay of the scheduler's start / RAW times), so the
   RTL is verified as the supply part of config C; the scheduler itself (tile order, shadow / lane drains) is R3's.
4. **int8 eot rides on the last item** (R2 had a separate S_CTEND cycle; the act-port stream and markers are
   identical).
5. **R2's int8 map path is not in qb_act2** (block 6 only from S); R2's qb_act remains as the one-context reference.
6. **HQ / HQD writer lane conflict** (S layout section) is left to R3 (rotation or write buffer) [E].
