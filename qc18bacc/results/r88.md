## Root cause [M] unless marked
- Writer [S]: signoff/pt/drv_eco.tcl:178 `remote_execute "write_changes -format icc2tcl -output $o/pt_eco.tcl"`
  (DMSA, first scenario).  PT man: icc2tcl = icctcl; the other formats are ptsh / text / dctcl / eco (binary, PT only),
  so no other format can be used.  Applied by icc2/eco.tcl `source $chg` with no rewriting [S].
- r88 change list: 39 add_buffer_on_route (24 DRC, 15 hold), 61 insert_buffer on a pin and 1 on a port, 32 size_cell,
  71 set_cell_location, 181 current_instance.  For each add_buffer_on_route, PT names the buffer's hierarchy only
  in the set_cell_location that follows.
- Failing pair (pt_eco.tcl:57-58, scope u_core): add_buffer_on_route on net of g_r_2__g_c_0__u_pe/u_shd/shd_reg_3_/Q,
  buffer U_PTECO_DRC_BUF15 BUFFD2 at (226.0, 1456.8) M5, then set_cell_location
  [get_cells g_r_2__g_c_0__u_pe/u_shd/U_PTECO_DRC_BUF15], which does not exist -> SEL-004 / SEL-005.
- That net (route label): driver shd_reg_3_/Q (286.6, 1464.8) and U24/A2 (284.4, 1457.6), both in u_shd, plus
  u_core/U435/I1 (151.4, 867.2) through the ports u_shd/shd[3] -> u_pe/shd[3] -> u_core/shd_2__0__3_.  The buffer
  drives U435/I1 only.  ICC2 created u_core/U_PTECO_DRC_BUF15 (input u_core/shd_2__0__3_, output
  u_core/eco_net_14_shd[3]).  PT named the same buffer inside u_shd, on the driver side of the boundary pin.  The
  electrical change is the same: one buffer in front of U435/I1.  Only the hierarchy differs, so PT's legal location was
  dropped: ICC2 put the cell at (225.4, 1457.6), PT had (225.4, 1455.8) FS, one row apart.
- ICC2 rule [S, add_buffer_on_route man]: by default the buffer goes in the lowest common ancestor hierarchy of the
  pins it drives.  The only other option is -on_top_hierarchy (top level).  No app option exists: eco.add_buffer_on_route.*
  holds only min_distance_buffer_to_load.
- ICC2 experiment (r89_diag/abor.tcl, route label opened read-only, never saved): the same command (A) as written,
  (B) with -punch_port, (C) with scope u_core/g_r_2__g_c_0__u_pe/u_shd.  All 3 put it at u_core/U_PTECO_DRC_BUF15,
  driving U435/I1 only.  So neither the scope nor -punch_port changes where ICC2 puts the buffer.
- PT side [S]: write_changes, insert_buffer, fix_eco_drc and set_eco_options have no option for the hierarchy of a new
  cell.  The eco_* variables (list checked) have none either.  insert_buffer man: at a boundary pin, the buffer goes
  inside or outside depending on current_instance.  This matches what PT did: BUF16 (same u_shd structure, cut next to
  the driver) is u_shd in both tools.  BUF14 (layer field 0) is u_core in both tools.  BUF15 (layer M5, cut after the
  internal load) differs.
- r87 had 27 add_buffer_on_route and no mismatch.  r88 has 39 with 1 mismatch.  This is a latent tool-convention
  difference, not a new flow bug.
