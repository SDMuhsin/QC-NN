# R46: why repair_timing -hold and repair_antennas segfault on the chip top r43_a
Labels: [M] measured, [S] from a report or source, [E] estimate. Jobs ran on tau6 only, one at a time. Inputs were r43_a
`db/grt.odb`, `grt.sdc`, `config.tcl` and the abs7 views, copied read-only from tau4 through a private NFS folder (now deleted).
Source was read at the build commit (`openroad 2.0-12381-g01bba3695`, conda 20240223, OpenSTA 2e59563). Line numbers refer to it.
Nothing is committed.

Both crashes are **OpenROAD bugs**, and our data triggers each one. Neither comes from threads or from the db being broken.
Each crash has a minimal repro and an opt-in fix, and the fixes have been run on r43_a.

## 1. Hold repair: an endpoint that is also a driver
**Bug (OpenROAD, confirmed).** `rsz::RepairHold::repairEndHold` (src/rsz/src/RepairHold.cc:385-455) walks the expanded
path from `startIndex()` to the end. For each driver vertex it reads the next vertex with `expanded.path(i + 1)->vertex()`.
If the last vertex is itself a driver with a violating fanout, `path(i + 1)` returns nullptr (sta/search/PathExpanded.cc:150).
The next dereference is the SIGSEGV. Upstream master copies the path vertices and stops one vertex short ("Stop one short of
the end so we can get the load") [S].

**Trigger (our data).** In `qb_act2_blk` (abs7 ETM, all corners), 24 output pins carry `setup_rising` / `hold_rising` arcs
clk -> pin (48 groups). Examples: `d_plane[*]`, `d_vld`, `d_ctx`, `d_chunk[*]`, `err` [M]. The reason is that `hw/rtl/qb_act2.sv:301/307` reads its
own outputs back into `dsc1`, so extract_model models an internal capture flop on each output port. To OpenSTA such a pin is a
check endpoint and a driver vertex at the same time. The hub and column ETMs have none [M].

**Evidence [M].**
* `impl/r46/hold46.tcl` + `hold46.gdb` run the hold43 placement-parasitics setting, which crashed in R43, under gdb.
* The fault is at `repairEndHold+3431  mov (%rax),%rax` with rax = 0.
* The last resizer trace lines show the endpoint vertex is its own driver:
  ```
  repair end u_act_blk/d_plane[2] hold_slack=-0.064 setup_slack=5.833
   u_act_blk/d_plane[2] hold_slack=0.005/-0.064 setup_slack=6.165/6.232 fanouts=1
  ```
* Hold false paths cannot remove these endpoints. `set_false_path -hold -to` the 24 pins gives STA-1551 "not a valid
  endpoint", because `Sdc::exceptionToInvalid` rejects pins with a clk -> Q arc. The run still found 3,220 endpoints and still
  crashed at the same PC [M].
* QB43_HOLDFP (60,893 dont_touch block inputs) never touched this class. The R43 r39_v "clean with HOLDFP" result is
  unexplained [S]. Section 3 shows HOLDFP has no effect on r43_a.

**Fix (opt-in `QB46_ETMO <dir>`, impl/r11/top.cfg).**
* OpenROAD reads `<dir>/<same lib name>` where that file exists. `impl/r46/etmochk46.py` writes it: the ETM with the
  setup_* / hold_* groups of output pins removed. Every other line is copied unchanged.
* Nothing is lost for the top repair. The path to such a check is clk -> output pin only, and upstream also buffers nothing
  for it.
* PT keeps the original ETM. The check is internal to the act block: d_plane[2] hold is -0.064 at placement parasitics. That is
  a block item: either register the outputs once, or stop reading output ports internally.

**Measured on r43_a [M].** hold43, placement parasitics, no GRT session:

| | crash runs | with QB46_ETMO |
|---|---|---|
| hold endpoints found | 3,220 | 3,213 (the 7 act output checks are gone) |
| repair | SIGSEGV | completes in 36 s, 1,755 hold buffers |
| tt after DPL + GRT, GRT parasitics, all exceptions restored | n/a | setup -1.709 (20 ep), hold -1.476 (18 ep) |

Before the repair, at placement parasitics, the tt numbers were setup -1.323 (4 ep) and hold -1.454 (1,735 ep). The keep-out
check found 0 overlaps.

## 2. Antenna repair: a mis-encoded via on an M1 global-route wire
**Bug (OpenROAD, confirmed).**
* `grt::RepairAntennas::makeNetWire` turns the GRT segments into a temporary dbWire.
* Take a wire segment on a layer below the min routing layer (M1) that ends on an M1 pin. `addWireTerms`
  (src/grt/src/RepairAntennas.cpp:298-304) takes the `conn_layer < min layer` branch. With `connect_to_segment` set and
  `tech_layer` (M1) != M3, it does `newPath(M1)` + `addTechVia(default_vias[M2])` = VIA23_1cut.
* `dbWireEncoder::addTechVia` (src/odb/src/db/dbWireCodec.cpp:371-395) finds M1 is neither the via's top nor its bottom layer.
  Its ZASSERT is compiled out, so it silently encodes TECH_VIA with via id 0.
* `odb::orderWires` -> `tmg_conn::loadWire` -> `dbWirePathItr::getNextShape` (dbWirePathItr.cpp:320-323) then calls
  `getBBox()->getBox()` on that non-via. The bbox is null, so the crash lands in `_dbBox::isOct`.
* It is deterministic, which is why 1 thread also crashed in R43.
* Upstream master rebuilt the antenna wires from guides. The encoder still writes id 0 silently [S].

**Trigger (our data).**
* The GRT route of `net5343` contains a wire on M1 (layer 1, outside M2-M9): (117000, 6363000) -> (123000, 6363000) dbu. It
  ends on `u_top_g_r3b_g_rt_u_seq/U46463/B2` (AOI22D2, M1 pin, x 118900-121100) [M].
* That net is fanout5343/Z (BUFFD16) driving 16 AOI22 inputs, with 262 segments.
* Suspected origin [S]: FastRoute layer assignment (src/grt/src/fastroute/src/utility.cpp:514-541). On an edge with no free
  capacity in the net's layer range, it makes layers below the min routing layer eligible. M1 has capacity 0 but is not
  excluded, so it ties at BIG_INT and wins when it saves vias next to an M1 pin. Not confirmed for this segment.
  The top GRT runs `-allow_congestion` with QB11_GR_ITER 5.

**Minimal repro [M]** (`impl/r46/repro46.tcl`, kit tech LEF only, no design data). One net, wire M1 (1000,1000) -> (5000,1000),
then `addTechVia`:
* VIA12_1cut (legal): encodes op 0x88 / operand 1, and the wire walk works (length 4000).
* VIA23_1cut (what RepairAntennas emits): encodes op 0x08 / operand 0. The decoded "via" has no name and a NULL bbox, and
  the wire walk segfaults.

**r43_a repro [M].** `impl/r46/ant46.tcl` + `ant46.gdb` load the db, run GRT with the flow settings and call `q43_ant`. The
SIGSEGV has the R43 backtrace. Recording the last `makeNetWire` call gives net5343 and its route above (`R46_SEG` lines).

**Fix: opt-in `QB46_ANTM1 1` in impl/r43/ant43.tcl. It is a BAND-AID until OpenROAD is patched.**
* GRT signal and clock min layer go to M1 for `repair_antennas` only, then are restored. M1 pins then join through the route's
  own M1-M2 via segments, and no via is mis-encoded.
* Check on net5343: 17 M1 pins, 17 via positions down to M1 [M]. All pins are connected without the else-branch.
* Not proven for every net [E].
* Measured [M]:
  * ant46 (grt.odb + GRT): 20 violations, 20 diodes, then 0. The repair takes 25 s.
  * Full hold43 step with QB46_ETMO + QB46_ANTM1: hold repair, then DPL, GRT and antenna repair. 21 violations, 21 diodes,
    then 0. Keep-out 0 overlaps. Timing is unchanged by the diodes (post_ant = post_hold above).
* Proper fix, not built: patch OpenROAD. The env has no swig, eigen or or-tools, and gcc is 8.5.
  * `addWireTerms`: when `tech_layer` is below the min routing layer, draw the pin connection on that layer and add no via.
  * `assignEdge`: never assign to layers outside the net's range (or with capacity 0).
  * `dbWireEncoder::addTechVia`: error on a via that does not fit the current layer.

## 3. Side results
* QB43_HOLDFP (R43 D2c) blamed the crash on the wrong pins: it false-paths dont_touch block inputs. On r43_a it changes nothing
  [M]. Run with QB46_ETMO and R43_HFPIN 0 (no false paths): 3,485 endpoints instead of 3,213, plus RSZ-0064 for the 272
  unrepairable block inputs. Still 1,755 buffers in 33 s, and the same post_hold numbers (setup -1.709 / 20, hold -1.476 / 18).
  The resizer already skips dont_touch nets. HOLDFP only hides those endpoints from its count, so it can be retired.
* QB43_ANT_THREADS was a symptom patch for a suspected thread race. There is no race; it is inert, and its comment is corrected.
* tau6 went down at 22:37 UTC (orderly shutdown entry, back 23:03) 3 minutes into the first ant46 run (GRT, about 10 GB RSS).
  Cause unknown. The rerun was identical and did not recur.
* M1 wires also reach the route guides that DR gets [E]. tau4 r43_a route.guide has about 30 interior M1 guide boxes wider
  than one gcell. That count is ambiguous, because merged pin-access boxes look the same. If the suspected origin holds, they
  mark GRT edges with no capacity left.
