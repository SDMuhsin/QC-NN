## 1. Antenna root cause on h125 (route_dr after the ECO) [M]
- Literal check_antennas: 746 nets / 862 pins, every one CAR vs Required 5000. Sinks: macro inputs 688 (qb_s 243,
  qb_p 227, qb_b 208, qb_f 10; M1-M3 pins), AOI22D0 98, DFQD1 31, ND2D0 30. Layer M4 416, M5 340, M6 178, M7 119.
  Mostly 2-pin nets (fanout p50 1); routed p10/50/90 883 / 1001 / 2765 um; driver -> sink 477 / 1163 / 2701 um.
- Layers: DR share of these nets = GRT guide share (M4 47.6 vs 46.7 %, M5 33.0 vs 32.0 %). DR does not push runs down.
- GRT estimate is not the miss: check_antennas on the GR wires (fresh GRT of grt.odb) flags 829 nets / 887 pins
  (415 nets shared with DR). GRT's repair_antennas found 4 (R28), in line with the LEF-rule count below [E: its own check credits diffusion].
- **Root cause: this OpenROAD build's checker ignores diffusion.** ant checkWireCar (2.0-12381, source read) uses the
  scalar ANTENNACUMAREARATIO whenever it is non-zero, so the LEF's ANTENNACUMDIFFAREARATIO PWL (5000 below 0.06 um2
  diff, 43027 at >= 0.06) is never applied. LEF semantics: the scalar is the rule for metal NOT connected to
  diffusion. Proof: net212701 (BUFFD16 Z, diff 1.456, joined to the gate's M4 trunk via M3/M2/M1) flagged at
  5346 / 5000; on b_q[102] 2 diodes placed 2 um from AOI22D0 B2 (first r29_hA try, 15 571 diodes) left 6240 / 5000.
- **LEF-rule check** (impl/r29/antd29.tcl: scalar CAR of M1-M8 set to 0 in memory, db not written, so the checker
  falls through to the PWL with the wire root's own diffusion): net212701 -> Required 43 711, clean.
  **h125: 746 -> 16 nets / 18 pins.** All 16 are macro-driven (qb_b QA -> b_q, qb_s QA -> s_mq) nets whose std-cell
  sink (AOI22D0 / ND2D0 / AOI22D1) hangs on a trunk the driver joins only above the checked layer [E]: genuine.
- R19/R20: the R20 hub reached 0 with the same checker (2.30 ns die, shorter nets); no setting to reuse.

## 3. PDN-under-pin (impl/r29/pdn29.tcl, opt-in R29_PDN)
- Each vertical macro-grid M4 strap is cut back to stay 1 um (y) clear of every macro M1-M3 signal pin within 0.2 um
  in x; its M3-M6 vias in the cut span are removed. h125: 1501 straps cut (3041 pin overlaps), 7026 vias removed.
- Result [M]: r29_hB DR reaches 0 with no ECO (the 26 NS-metal markers do not occur); r29_hA (same diodes, straps
  kept) stalls at 27 like R28. check_power_grid on hB: VDD and VSS all stripes connected. Applied as an odb edit on
  the GRT db (9 min Tcl); the root form for a fresh run is the same proc after pdngen (MACRO_PDN_TCL hook).
- Full-die check_drc on hB [M]: 7, all single-net M2 "Metal Spacing" with 0.02-0.06 um boxes (the class R28 traced
  to DRT patches that check_drc does not load; h125 had 8 + 1 two-net). No two-net marker on hB.
## 4. Timing on routed h125 (measurement only) [M]
- Not annotated 46 474 nets: 40 292 top-level undriven (u_top_n 34.8k, g_wbq_fyq 4.3k, s_wd, bw_d: no timing
  effect), 560 undriven hierarchical, 5 622 driven nets whose name has an escaped '/' (CTS clknet_* of hierarchical
  ICG nets ~4.5k, ICG latch/Q nets): def2spef --escape-divider writes the pin as 'clkbuf_0_u_head\\\/...' and PT
  drops the net (PARA-044 / PARA-124). The 3 worst reg2reg paths (52 nets each with clock) have 0 such nets.
- Worst 3 reg2reg (tt, 3.40): qb_s CLKA -> QA -> rq_r_reg D, one unbuffered net each, no cells between:
  s_mq[3313] 1.02 pF, D slew 6.92 ns, wire 2.69 ns, setup 1.02 (-1.55); s_mq[3469] 0.90 pF, 8.30, 2.80 (-1.54);
  s_mq[3073] 1.00 pF, 7.63, 2.40 (-1.40). Routed 3.6-4.1 mm (macro y 185 -> flop y 2340 + 4 AOI22 at y 1900),
  mostly M4/M6/M9. Launch latency 1.70 vs capture 1.41.
- **Why OR's estimate is better:** OpenROAD expands the SDC line `set_case_analysis 0 [get_pins -hierarchical */EMA*]`
  to 2098 pins, 1816 of them macro QA outputs (45-47 per qb_b / qb_s); write_sdc carries them into every db/*.sdc.
  All 3 worst PT startpoints are among them; OR shows every CLKA -> QA arc "Disabled by constant". So placement,
  repair_design / repair_timing and the placement estimate (3.34 ns, r26_p1) never see these paths and leave them as 4 mm bare wires.
  Pattern test (OpenSTA get_pins -hierarchical): */EMA* 2098 pins (1816 QA), */EMAA* 1656 (1440 QA), */EMAB* 496
  (376 QA); */EMA\[* 42 (0 QA). OpenSTA's bus wildcard matches QA[0-24] / QA[100+] (e.g. g_s_6), PT does not.
- **PT tt reg2reg at 3.40 with those 1816 QA pins excluded: worst -0.131 (3.53 ns, 283 MHz)** vs -1.553 (201.9 MHz)
  with them. 157 of the 158 violating reg2reg endpoints pass through such a QA pin. So the 3.34 -> 4.95 ns gap is
  the paths OR never timed, not extraction or routing detour. Fix for later (not applied): emit bracketed patterns
  (*/EMA\[*, */EMAA\[*, */EMAB\[*) in impl/r9b/sdc.py so OR times, places and buffers the macro-output nets.
