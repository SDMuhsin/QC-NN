## Prediction (written before the run)
Predicted failure points, most likely first [E]:
1. **ss setup with real SI** (coupling kept, ~2.03 M coupling caps now in PT): delta delays of 20-80 ps on the long
   vertical act / act_o and south-port nets. ICC2 already ran SI, so reg2reg stays clean; risk is the IO classes
   (act2act_o, reg2south) where r62 margin was smallest: 0-30 setup endpoints after route, which the PT ECO does not fix
   (it fixes DRV + hold only) [E: 35 %].
2. **ff hold with SI** (crosstalk speed-up): 100-400 endpoints before ECO round 1 (r62: 204 without real SI), 0-10 after
   round 1, 0 after round 2-3 [E].
3. **ss DRV on act_o**: the act_o load rises from 0.0187 pF to the per-bit own act net (p50 ~0.04, max ~0.09 pF). ICC2
   sees it only from cts on (place_opt still uses the DC constant), so the size_only feedthrough buffers may be undersized
   after place; expect 0-50 max_transition / max_cap pins on act_o after route, fixed by route_opt / PT DRV ECO [E].
4. **qb_io_load** (new ICC2 code before clock_opt and route_opt): set_load clears the net parasitics (TIM-123), so
   route_opt re-extracts; risk of a Tcl error stopping the cts step [E: 15 %].
5. **ETM**: with set_max_transition on the inputs the input max_transition should read 0.5 ns; risk that extract_model
   still writes the context slew (then 0) and etmcheck fails [E: 25 %]. MEXT-81 gone with the clk driving cell removed.
6. **Reduced coupling count**: PT prints "Reduced coupling capacitances : 0" or omits the line; XTALK-011 gone [E].
7. Calibre / LVS / antenna: unchanged from r62 (M8/M9 density only, CORRECT 12356, 0) [E].

**PI scope addition (08:58 UTC, before the derate run):** flat OCV derate late 1.05 / early 0.95 (cell + net, clock +
data, every corner) in ICC2 and PT. The first r64 launch (no derate) was stopped after route (its route QoR is kept in
r64/summary_noderate.txt: ss setup NVE 1 at -0.00, ff hold NVE 18 at -0.00, DRV 6) and r64 restarted from place.
Added predictions [E]:
8. **ss setup with the derate**: +5 % on ~4.7 ns reg2reg arrivals is ~0.24 ns. The r62 reg2reg slack was 2.2 ns at 6.5 ns,
   so reg2reg closes. The act -> act_o feedthrough class (0.55 P in + 0.38 P out budget) is the tightest: r62t was already
   -0.17 ns with the new load, so ICC2 has to upsize the feedthroughs. Risk 0-50 act_o setup endpoints [E: 35 %].
9. **ff hold with the derate**: early 0.95 on data and the late 1.05 on the capture clock cost ~5 % of the clock
   insertion delay (~17 ps at ff) on every hold path minus CRPR. Expect 300-1500 ff hold endpoints after route. The PT
   ECO should take them to 0 in 2-3 rounds, but the area of the hold buffers grows [E].

## Fixes (root causes)
1. **SI sign-off was not real** [M]. `read_parasitics` grounds every coupling capacitance unless it is given
   `-keep_capacitive_coupling`; `si_enable_analysis true` alone does not keep them (r62: "Reduced coupling capacitances :
   2029860", XTALK-011).
   - Shared fix: `signoff/pt/common.tcl` `qb_pt_spef` (read with coupling). Every PT reader uses it: col_blk, act_blk,
     hub (now sources common.tcl before the SPEF), top_chip (now sources common.tcl), etm. The DMSA ECO sources
     col_blk.tcl, so it is covered too.
   - Gate in `common/env.sh` `qb_pt` (every PT run of every block): fails on any XTALK-011 or a non-zero "Reduced
     coupling capacitances" in the logs that run wrote (main log, ./parasitics_command.log, DMSA scenario out.log /
     parasitics_command.log). The PT_ERRORS line also logs "coupling_annotated" (PT prints "Annotated coupling
     capacitances", and the reduced line only when it grounds coupling). parasitics_command.log is kept per run as
     `<log>_parasitics.log`.
   - `qb_pt_ann` (common.tcl) replaces 5 copies of the annotation parse: with coupling kept, report_annotated_parasitics
     has a "Coupled network" column, and the old regex reported coupled nets as not_annotated (r62t: 206335).
   - Wrong comment at common.tcl:10-11 rewritten.
2. **Abstract dropped clk antenna data** [S]. `icc2/abstract.tcl`: clk has port_type `clock` [M]. The filter is now
   `port_type!=power && port_type!=ground`.
3. **act_o load** [M]. Column c's act_o[b] drives column c+1's act[b]: same bit, same y, identical block. So the load is
   this block's own act[b] net capacitance (pins + wire), per bit.
   - `blocks/col/io_budget.tcl`: `qb5_act_o_caps` measures, `qb5_act_o_load` applies. They are separate because a
     set_load invalidates the timing; ICC2 also clears the net parasitics (TIM-123) and then reads empty or 0 caps [M].
   - PT (col_blk.tcl, so also the DMSA ECO): net `total_capacitance_max` on the routed SPEF.
   - ICC2: `qb_io_load` (icc2/common.tcl, hook `P(IO_LOAD)` in blocks/col/icc2.cfg) reads port `max_rise_load_cap`
     per scenario. On r62, ICC2 = PT exactly: act[0] ss 0.067407 pF [M]. It runs in cts.tcl before clock_opt
     (placement estimate) and in route.tcl after route_auto (routed). place_opt still sees DC's 4 x INVD4 (no wires yet).
   - Per bit, not max: bit b's load is exactly the same net in the next column. The max (r62 ss 0.088 pF) would
     over-load the p50 bit (0.037) ~2.4x on most of the 4608 feedthroughs.
   - [M] r62 layout re-timed with this load (r62t, SI on): ss setup 555 + max_tran 3184 + max_cap 655, ALL on
     act_o / feedthrough drivers; act2act_o -0.174 ns, feedthrough max 0.629 vs 0.455 budget. ff hold 1, tt DRV 189/161.
     So r62 was signed off against a too-light act_o: the full rerun is required.
4. **ETM clk slew** [M]. `qb_etm_inputs` now removes the driving cell on every input, clk included. r62t: MEXT-81
   0 (was 2 per ETM).
5. **ETM max_transition 0** [M]. extract_model writes an input pin's max_transition = its port's context slew.
   - Tested on r62 tt: input transition 0 -> 0; 0.2 -> 0.2. A port set_max_transition and the
     extract_model_*_transition_limit variables both leave it at 0.
   - Fix: input transition = design max_transition (min(0.5, 0.1 P) = 0.5 ns) on every input. The tables are
     characterised up to the same limit (was 5 ns).
   - `etmcheck.py` now reports input-pin max_transition and exits 1 on any missing or 0 value.
   - run.sh `post` fails on MEXT-81 / MEXT-97 in an ETM log.
   - r62t tt: 6959 inputs at 0.5, 0 missing, MEXT-81/97 0.
8. **views label** [S]. run.sh `views` now defaults QB_ICC2_LABEL to out/label.txt (else route), as eco.
9. **Stale ICC2 IO latency** [M]. Matters, so fixed natively:
   - ICC2 times the IO paths of a propagated clock with the latency compute_clock_latency sets (man page). It was
     computed once at CTS: ss 0.815 / tt 0.530 / ff 0.372 vs routed PT p50 0.724 / 0.475 / 0.339.
   - So route_opt timed reg->out 91 ps optimistic and in->reg pessimistic at ss.
   - `icc2/route.tcl`: compute_clock_latency before each route_opt.
10. **OCV derate (PI addition)** [M]. `common/derate.tcl` (`qb_derate`: set_timing_derate -late 1.05 / -early 0.95,
    -cell_delay -net_delay, clock + data) is the one definition.
    - ICC2: `qb_timer` (icc2/common.tcl) applies it on every scenario; init.tcl calls qb_timer again once the
      scenarios exist.
    - PT: signoff/pt/common.tcl, so block sign-off, DMSA ECO, ETMs and top all get it.
    - Checked with report_timing_derate on r62: ICC2 func_ss / func_ff and PT both show 0.95 / 1.05 on cell, net
      static and net dynamic.
11. **ECO zero-change round** [M]. Round 2 had nothing left to fix, so PT write_changes wrote no file and drv_eco.tcl
    failed on `exec cat`. Fix: it now writes an empty list.
12. **Clock-network DRV** [M]. Rounds 1 and 2 left 2 ss max_cap on clock-gate outputs that the data pass never
    touches. Fix: qb_eco_drc adds a `-cell_type clock_network` size_cell pass.
    - It is not physically aware. PT 2019.12 reads clock physical data from DEF only (PTECO-038), and ICC2 eco.tcl
      legalises the sized cells.

## Findings 6 / 11 (suspected items)
6. **act input budget is right** [S]. The chip core has **8** columns, not 16. synth/chip_core_blk.sv instantiates
   hw/tb/qb_colarr.sv with COLS 8; blocks/top/top.cfg has "hub + act + 8 columns".
   - act enters column 0 from the act block on the west (top_fp.py) and chains through act -> act_o, so it is a
     7-deep chain, not fed from the middle.
   - Column 7 is the worst: launch + top wire 0.06 P + 7 x 0.07 P = 0.55 P, which is the budget. No change.
   - The feedthrough budget of 0.07 P (0.455 ns) holds in r64: ss feedthrough max 0.390 ns with the real per-bit load,
     SI and derate [M]. On the r62 layout with the new load it was 0.629 ns.
11. **DC D0 cells** [M]. The DC netlist has 15,416 *D0 instances of 13 masters: MUX2ND0 9984, AO22D0 1428, HA1D0 986,
    MUX2D0 841, FA1D0 804, AOI222D0 758, NR4D0 261, ... The routed r62 netlist still has 15,216 (MUX2ND0 9975).
    - Cause: `flow/tsmc65/site/site.tcl:21 set ::QC_DONT_USE {}`, read by `flow/tsmc65/syn/dc.tcl:21-22`. DC therefore
      has no dont_use, while P&R excludes `*D0` (`site/pnr.tcl:25 QC_PNR_DONT_USE`).
    - ICC2 keeps the existing D0 instances: it cannot size to or from them. Not re-synthesised (out of scope this round).
