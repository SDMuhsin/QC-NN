# R68: column qb_col_blk, kit sign-off corner set, fill-aware extraction, fixed-size act feedthroughs, full rerun r68

Run: tau5 `/tmp/ckp908/qc18bacc/build/icc2/col/r68` (ICC2 Q-2019.12-SP2, PrimeTime Q-2019.12-SP2, Calibre 2026.1).
Labels: [M] measured, [S] read from source (kit / tool / code), [E] estimated.

## Prediction (written before the run)

1. libs: the NDM is rebuilt with the wc / wcl / tc / lt / ml .db (5 libraries, was 3). Low risk.
2. init: 9 scenarios. `set_operating_conditions WCLCOM` / `MLCOM` should resolve in the merged NDM. Risk: an opcond
   that matches several libraries (low). The feedthrough `size_cell` + `dont_touch` on 4608 cells and 4608 act_o nets
   should run clean.
3. place / cts / route: the runtime is about 2-3x r67 (9 scenarios vs 3) [E], so pnr takes about 1.5-2 h. The most
   likely ICC2 residues:
   - max_transition on act_o nets, because the dont_touch nets cannot be re-buffered and the BUFFD4 may sit far from
     the east edge;
   - hold at the new ml / RCbest corners, where hold buffers conflict with setup at wcl on the same short paths.
4. act -> act_o: BUFFD4 meets 0.07 P at wcl/Cworst with 0.044 ns of slack on the r67 layout [M]. RCworst is not
   measured; there the slack should drop by about 10-30 ps [E]. That is the most likely failure: wcl_rcw or ss_rcw
   act2act_o slack slightly < 0.
5. fill/extract: read_def of the 1.9 M FILLS took 4 s on r67 [M]. Risk: the SPEF names fill nets or carries
   floating-fill coupling that PrimeTime rejects (SPFP errors -> the qb_pt gate). Medium.
6. eco: DMSA with 9 scenario processes at ~2-3 GB each is ~20-27 GB on a 30 GB host [E]. Risk of memory exhaustion
   (medium).
7. post: the new ml (FF, 125 C) corner is the most likely to show noise / glitch violators, because it has the fastest
   edges with the highest leakage. wcl is the most likely setup corner (temperature inversion at 0.9 V). reg2reg has
   1.6 ns of slack at ss in r67 [M], so if anything fails it is act -> act_o.
8. Calibre DRC / LVS / antenna: unchanged from r67 (the fill is the same deck). Expected: DRC only M8/M9 density, LVS
   CORRECT 12356 ports, antenna 0.

## 1. Sign-off corner set (kit) [S]

- Kit release note `Documentation/release_note/RN_TCBN65GPLUS_140B.pdf`, section 5 NOTE, I. "Base characterization
  corners" [S]:

  | corner | V | T (°C) | process |
  |---|---|---|---|
  | BCCOM | 1.1 | 0 | FF |
  | LTCOM | 1.1 | -40 | FF |
  | MLCOM | 1.1 | 125 | FF |
  | NCCOM | 1.0 | 25 | TT |
  | WCCOM | 0.9 | 125 | SS |
  | WCLCOM | 0.9 | -40 | SS |
  | WCZCOM | 0.9 | 0 | SS |

  Every one is in `Front_End/timing_power_noise/CCS/tcbn65gplus_200a` as `tcbn65gplus{bc,lt,ml,tc,wc,wcl,wcz}_ccs.db`.
- The note has no sign-off recommendation beyond this table. The standard set it implies:
  - setup at the slow process and low voltage at both temperature ends: WC and WCL (WCL is the temperature-inversion
    corner);
  - hold at the fast process and high voltage at both ends: LT and ML;
  - TC for typical.
- BC and WCZ (0 °C) are not used. They lie inside the -40..125 °C span of the same process and voltage [E].
- RC: kit `techfiles/tluplus` has 1p09m `cworst`, `rcworst`, `typical`, `cbest` and `rcbest` (`_top2`) [S]. Setup uses
  {Cworst, RCworst}, hold uses {Cbest, RCbest}.
- Implemented set (9 scenarios):
  - setup: `ss` (wc/Cworst), `ss_rcw` (wc/RCworst), `wcl`, `wcl_rcw`;
  - hold: `ff` (lt/Cbest), `ff_rcb`, `ml` (ml/Cbest), `ml_rcb`;
  - `tt` (tc/typical, hold role in ICC2).
- PrimeTime checks setup, hold, DRV, noise and pulse in every scenario.
- One table, `flow/tsmc65/site/site.tcl` `QC_SIGNOFF` (template in `site.example.tcl`), defines everything else:
  `QC_LIB`, `QC_OC`, `QC_TLU_FILE`, `QC_ROLE` and `QC_SIGNOFF_CORNERS` are all derived from it.
  - ICC2 (`icc2/libs.tcl` NDM with 5 libraries, `icc2/init.tcl` MCMM) reads the table.
  - PrimeTime (`signoff/pt/col_blk.tcl`, DMSA `drv_eco.tcl`) reads it through `QC_CORNER`.
  - bash reads it through `common/env.sh qb_corners [signoff|base]`, which uses tclsh on site.tcl itself.
- ETM / top consistency:
  - The base corners `QC_CORNERS {ss tt ff}` are a subset of the table. DC, the OpenROAD act / hub / top flows and the
    chip-top block views use them.
  - `blocks/col/run.sh post` writes ETMs for exactly `qb_corners base`.
  - `blocks/top/run.sh views` and `blocks/top/top.cfg` (`MACRO_LIBS_<c>`) iterate the same list. So the ETM set and the
    top's corners come from one variable and cannot drift.
  - The top's own sign-off corner expansion is open; the top is not rerun in R68.

## 2. Metal fill vs extraction

- Kit TLU+ (ASCII ITF header of `cln65g+_1p09m+alrdl_cworst_top2.tluplus`) [S]:
  - Every metal has `POLYNOMIAL_BASED_THICKNESS_VARIATION` with `DENSITY_POLYNOMIAL_ORDERS`. This is thickness versus
    density (CMP), plus `USE_SI_DENSITY = YES`.
  - There is no `FILL_RATIO` / `FILL_SPACING` / `FILL_WIDTH` / `FILL_TYPE` emulation keyword.
  - So the TLU+ does not model the dummy-fill capacitance.
- ICC2 Q-2019.12 [S]: `set_extraction_options -real_metalfill_extraction none|floating|grounded|auto`. The default is
  `none`; `report_extraction_options` on r67 shows `none`. `read_def -include fills` reads DEF FILLS.
- Implemented (native):
  1. `run.sh fill`: Calibre dummy metal of the outputs GDS (`cal.sh fill`, as before).
  2. `signoff/calibre/fill_def.py` (klayout) converts DM.gds to DEF FILLS: GDS layer 30+i, datatypes 1 (DM) and 7 (RM),
     to Mi.
  3. `icc2/extract.tcl`: `read_def -include fills`, then `-real_metalfill_extraction floating` (Calibre dummies are
     unconnected), then `write_parasitics`, one SPEF per sign-off corner. The block is not saved.
  4. `calibre` signs off on the same filled GDS. It fails if that GDS is older than the outputs GDS.
  - `outputs.tcl` no longer writes SPEFs.
- Probe on the r67 eco label with r67's own 1 903 515 fill shapes [M]:
  - read_def took 4 s.
  - ICC2 func_ss / Cworst at the P&R SDC (5.0 ns); total capacitance, no fill -> floating fill:

    | net | no fill (fF) | floating fill (fF) | delta |
    |---|---|---|---|
    | act[2274] | 19.37 | 21.05 | +8.7 % |
    | p_abuf7 (u_rlate) | 368.65 | 371.94 | +0.9 % |
    | HFSNET_15 (g_fin2_u_fa) | 38.55 | 39.04 | +1.3 % |
    | n209 | 23.01 | 23.22 | +0.9 % |
    | n197 | 2.46 | 2.36 | -4 % (floating fill splits coupling) |
    | act[961] | 56.42 | 56.45 | 0.05 % |

  - Most of the 35 sampled nets change by under 1 %.
  - Timing deltas:
    - worst reg2reg slack: 0.2328 -> 0.2410 ns (+8 ps);
    - worst hold slack: +0.012 ps -> -0.496 ps (-0.5 ps);
    - act[961]->act_o[961]: +0.15 ps.
  - `none` reproduces the no-fill numbers exactly. So the fill shapes are what changes the extraction.

## 3. act -> act_o feedthrough size [M]

- PrimeTime sweep on the r67 netlist and SPEF (Cworst) at 6.5 ns:
  - all 4608 act_o drivers were sized to X;
  - act[*] driving cell = X;
  - act_o load = the per-bit act net capacitance (re-measured per X).
- Feedthrough delay = act_o arrival − (0.55 P + L). Budget 0.07 P = 0.455 ns.

  | X | wcl max delay (ns) | wcl bits over | wc (ss) max delay (ns) | ss bits over |
  |---|---|---|---|---|
  | BUFFD1 | 1.530 | 4164 | – | – |
  | BUFFD2 | 0.779 | 152 | – | – |
  | BUFFD3 | 0.552 | 3 | 0.405 | 0 |
  | BUFFD4 | 0.411 | 0 | 0.359 | 0 |

- wcl (temperature inversion) is the worst setup corner for this path. BUFFD4 is the smallest size that meets the budget
  there, with 44 ps of slack, so `QB5_FT {BUFFD4 Z}`.
- RCworst was not part of the sweep. r68 sign-off measures it.
- Implementation:
  - `icc2/init.tcl` P(FEEDTHRU) + P(FEEDTHRU_CELL) from `io_budget.tcl QB5_FT`;
  - `size_cell` + `set_dont_touch` on the 4608 cells and on their act_o nets (no re-buffering, so the port's driver
    stays exactly QB5_FT);
  - `qb5_io_lines` carries `set_driving_cell -lib_cell BUFFD4 -pin Z act[*]` for ICC2 and PT alike;
  - PT `col_blk.tcl` checks every act_o driver is BUFFD4 (`qb5_ft_cells`, error otherwise) and dont_touches cells +
    nets, which the DMSA ECO inherits.
  - Removed as dead: `qb5_act_drv` / `qb5_act_drv_apply`, `P(IO_DRIVE)`, `qb_io_drive`.
- The gate works [M]: the r67 netlist fails it (3831 drivers not BUFFD4).

## Mid-run fix (own bug)

- The first `extract` failed with "no SPEF for corner ss".
- Cause: `write_parasitics` names each file `<top>.<parasitic tech>_<T>.spef`. In r67 the tech names equalled the corner
  names. R68 names the techs after their TLU+ file, so they are shared by corners.
- Fix: `icc2/extract.tcl` maps the files to corners through the tool's own `<top>.spef_scenario` list.
- Queue r68q2 resumed from `fill`. The routed block was unaffected.

## Gate gap found and fixed (not yet exercised by a run)

- `post` did not gate setup, hold or DRV. `qb_pt` counted only noise / pulse / period from QB_PT_SIGNOFF, so the 3 ml
  max_tran violators passed it, and only ml_rcb noise stopped the step.
- Fix: `col_blk.tcl` prints `QB_PT_SIGNOFF setup N hold N max_transition N max_capacitance N`, using the return value
  of `qb_pt_drv`, which act / hub / top ignore, so they are unchanged.
